# Codex Windows Git Bash shell investigation

## G1 verdict: patch existed, and the relevant pieces are recoverable

**Verdict:** yes, the Git Bash shell-selection support existed in the fork history, but the current default path no longer auto-selects Git Bash. The recoverable commits are:

- `1d828e59477b812ac8299e70c2c20f9f80f50ab3` (`fix(launcher): drop default_model + copilot_api_port; add where git shell scan`) for the Git Bash detector and first-run shell prompt.
- `fff065934c281bfd3df825eaadbb768722ac4576` (`fix(launcher): enable unified_exec for Git Bash on Windows`) for removing the old `features.unified_exec=false` blanket Cygwin/MSYS guard.

The old launcher explicitly carried a `default_shell` config field and emitted `default_shell=<path>` into codex-core `-c` flags when present (`1d828e5947:codex-rs/codex-copilot-launcher/src/config.rs:3-5`, `1d828e5947:codex-rs/codex-copilot-launcher/src/config.rs:55-78`). Its first-run setup prompted with "PowerShell (default)" and a detected "Git Bash" option, then wrote the selected absolute shell path into `~/.codex-copilot/config.toml` (`1d828e5947:codex-rs/codex-copilot-launcher/src/setup.rs:131-163`, `1d828e5947:codex-rs/codex-copilot-launcher/src/setup.rs:113-128`). The detector preferred real Git-for-Windows layouts before falling back to `where bash`: hard-coded `C:\Program Files\Git\bin\bash.exe`, `C:\Program Files (x86)\Git\bin\bash.exe`, `%LOCALAPPDATA%\Programs\Git\bin\bash.exe`, then `where git` resolved to sibling `bin\bash.exe`, and only then `where bash` (`1d828e5947:codex-rs/codex-copilot-launcher/src/setup.rs:182-210`, `1d828e5947:codex-rs/codex-copilot-launcher/src/setup.rs:216-245`). That ordering directly avoids the Windows PATH gotcha where bare `bash` may resolve to WSL's `C:\Windows\System32\bash.exe` before Git Bash.

The current launcher still has those first-run pieces: it reads `default_shell` from `~/.codex-copilot/config.toml` (`codex/codex-rs-overlay/codex-copilot-launcher/src/config.rs:10-28`, `codex/codex-rs-overlay/codex-copilot-launcher/src/config.rs:63-70`), emits `default_shell=<path>` when configured (`codex/codex-rs-overlay/codex-copilot-launcher/src/config.rs:80-108`), prompts for PowerShell/Git Bash/Other on first run (`codex/codex-rs-overlay/codex-copilot-launcher/src/setup.rs:137-169`), and retains the same Git Bash detection order (`codex/codex-rs-overlay/codex-copilot-launcher/src/setup.rs:188-216`, `codex/codex-rs-overlay/codex-copilot-launcher/src/setup.rs:222-267`). What is not present is a codex-core default-off feature that makes Git Bash the Windows default when no launcher `default_shell` override exists.

The subtree-to-submodule migration did happen in the wrapper line: wrapper docs say W-5 evolved the fork layout so the patched upstream checkout lives as a submodule at `external/repos/codex-patched/` with overlay crates at `codex-rs-overlay/` (`codex/CLAUDE.md:34-43`), and the topology docs identify `external/repos/codex-patched/` as the git submodule carrying the patched upstream source (`codex/docs/workflows/repo-topology.md:11-17`, `codex/docs/workflows/repo-topology.md:110-118`). `git -C codex log --all --grep subtree|submodule` also found migration/follow-up commits including `5359bc448` (`feat(US-005): convert external/repos/codex-patched from subtree to submodule`), `99eb8f1cc`, and `d1d7c933b`. The inner repo's normal ancestry is not fully continuous with upstream refs on this checkout (`git diff upstream/main...HEAD` failed with "no merge base"), so the operator's "history was lost/truncated" suspicion is directionally plausible for normal ancestry traversal. The important patch content is nevertheless still reachable from local refs in `codex/external/repos/codex-patched`.

The patch registry is also an orphaned clue for the old launcher behavior. The wrapper registry says `provider_config_flags` retained `default_shell=<path>` and that `setup.rs::detect_git_bash()` added the `where git` step; it also records that the earlier Cygwin/MSYS `features.unified_exec=false` blanket disable was removed in `v0.128.0-copilot-api.2` (`codex/docs/implementation/patch-surface.md:397-400`). Its invariant table forbids reintroducing the `features.unified_exec=false` guard because `exec_command` defaults to `tty=false` and Git Bash pipe I/O is safe (`codex/docs/implementation/patch-surface.md:797-801`, `codex/docs/implementation/patch-surface.md:1760-1764`). The smaller inner registry currently has no shell-selection/Git-Bash row (`rg` for `default_shell|detect_git_bash|Git Bash|PowerShell` in `codex/external/repos/codex-patched/docs/implementation/patch-surface.md` returned no matches), so the live registry evidence is wrapper-side only.

Remotes are available for comparison/recovery: the inner repo has `origin`/`codex-patched` at `https://github.com/Evyatar108/codex-openai-fork.git` and `upstream` at `https://github.com/openai/codex.git`; the wrapper repo `origin` is `https://github.com/gim-home/codex.git`. The current source shows Windows PowerShell defaulting is upstream-native in codex-core rather than a launcher-only fork behavior (see G2), while auto-defaulting to Git Bash would be fork-divergent.

## G2 current-code map: where Windows default shell is selected today

The current codex-core Windows default is chosen in `core/src/shell.rs`. `default_user_shell()` delegates to `default_user_shell_from_path(get_user_shell_path())` (`codex/external/repos/codex-patched/codex-rs/core/src/shell.rs:312-314`). On Windows, `default_user_shell_from_path()` ignores the OS/user shell path and directly returns `get_shell(ShellType::PowerShell, None).unwrap_or(ultimate_fallback_shell())` (`codex/external/repos/codex-patched/codex-rs/core/src/shell.rs:316-319`). PowerShell lookup first tries `pwsh`/PowerShell 7 fallback paths, then `powershell`/Windows PowerShell fallback paths (`codex/external/repos/codex-patched/codex-rs/core/src/shell.rs:236-260`). If no PowerShell-like shell is found, the ultimate Windows fallback is `cmd.exe` (`codex/external/repos/codex-patched/codex-rs/core/src/shell.rs:280-286`).

`get_shell_path()` first accepts an exact provided path, then a detected user shell when it matches the requested shell type, then `which::which(binary_name)`, then static fallback paths (`codex/external/repos/codex-patched/codex-rs/core/src/shell.rs:165-198`). The generic Bash path uses `which::which("bash")` and `/bin/bash` fallback (`codex/external/repos/codex-patched/codex-rs/core/src/shell.rs:212-221`). That generic Bash lookup is not safe as a Windows Git Bash auto-default because it can resolve WSL bash first; a re-add must prefer the launcher detector's Git-for-Windows paths and `where git` layout before any bare `bash` PATH lookup (`codex/codex-rs-overlay/codex-copilot-launcher/src/setup.rs:188-216`, `codex/codex-rs-overlay/codex-copilot-launcher/src/setup.rs:222-267`).

The selected shell is installed at session construction. `Session::new` chooses, in order, an explicit `user_shell_override`, the zsh-fork feature shell, or `shell::default_user_shell()` (`codex/external/repos/codex-patched/codex-rs/core/src/session/session.rs:840-860`). It then attaches a shell snapshot receiver to that selected shell (`codex/external/repos/codex-patched/codex-rs/core/src/session/session.rs:861-880`). This is the cleanest core seam for a feature-gated Git Bash default: insert a branch before the `shell::default_user_shell()` fallback when no explicit shell override and no zsh-fork shell are active.

Tool execution then uses the session shell. Unified exec's `get_command()` takes `session_shell`, uses an optional model-supplied `shell` only when present, otherwise defaults to `session_shell`, and calls `shell.derive_exec_args(...)` (`codex/external/repos/codex-patched/codex-rs/core/src/tools/handlers/unified_exec.rs:98-125`). The shell-derived args use `bash -c/-lc` for `ShellType::Bash`, `powershell/pwsh -NoProfile -Command` for `ShellType::PowerShell`, and `cmd /c` for `ShellType::Cmd` (`codex/external/repos/codex-patched/codex-rs/core/src/shell.rs:41-69`). Legacy shell-command tool descriptions still say Windows runs PowerShell (`codex/external/repos/codex-patched/codex-rs/core/src/tools/handlers/shell_spec.rs:181-196`), so a Git Bash feature may need text/tool-description tests if it affects visible guidance.

## G3 feasibility and scope: default-off experimental feature

This is feasible as a small, default-off experimental feature. The feature registry already supports visible `/experimental` entries via `Stage::Experimental { name, menu_description, announcement }` (`codex/external/repos/codex-patched/codex-rs/features/src/lib.rs:28-45`, `codex/external/repos/codex-patched/codex-rs/features/src/lib.rs:47-72`). Fork-local visible features use the same pattern and default off: `Feature::LegacyPasteBurstHeuristic` is declared beside other `SANDBOX PATCH` feature IDs (`codex/external/repos/codex-patched/codex-rs/features/src/lib.rs:137-145`) and registered as key `legacy_paste_burst_heuristic` with `Stage::Experimental` and `default_enabled: false` (`codex/external/repos/codex-patched/codex-rs/features/src/lib.rs:1005-1017`); `Feature::UserMessageStyling` follows immediately with key `user_message_styling`, visible menu metadata, and `default_enabled: false` (`codex/external/repos/codex-patched/codex-rs/features/src/lib.rs:1018-1030`).

Recommended feature shape:

- Add `Feature::WindowsGitBashShell` after nearby fork-local shell/user-experience gates in `features/src/lib.rs`, with a `// SANDBOX PATCH:` marker and doc comment like "Use Git Bash as the default Windows shell when no explicit default_shell is configured. Default off." The exact enum insertion point should be near `AutoLoadClaudeMd`, `LegacyPasteBurstHeuristic`, and `UserMessageStyling` (`codex/external/repos/codex-patched/codex-rs/features/src/lib.rs:137-145`).
- Add a `FeatureSpec` entry near those same fork-local specs, key `windows_git_bash_shell`, `Stage::Experimental { name: "Windows Git Bash shell", menu_description: "Use Git Bash as the default shell on Windows when detected.", announcement: "Windows Git Bash shell can now be enabled from /experimental. Restart Codex after enabling it." }`, `default_enabled: false` (`codex/external/repos/codex-patched/codex-rs/features/src/lib.rs:993-1030`).
- Gate in `core/src/session/session.rs` because both the resolved `Config` and its `features` are already available there (`codex/external/repos/codex-patched/codex-rs/core/src/session/session.rs:840-860`). The branch should run only when `user_shell_override` is absent and `Feature::ShellZshFork` is not active; explicit launcher/config shell should continue to win (`codex/external/repos/codex-patched/codex-rs/core/src/session/session.rs:840-860`).
- Add a Git Bash detector that does **not** use bare `which("bash")` first. Prefer a new small helper in a new file/module (for example `core/src/windows_git_bash.rs` behind `#[cfg(windows)]`) copied/adapted from the launcher detector: hard-coded Git-for-Windows paths, `%LOCALAPPDATA%\Programs\Git\bin\bash.exe`, `where git` to sibling `bin\bash.exe`/`usr\bin\bash.exe`, then optional last-resort `where bash` only after those safer candidates (`codex/codex-rs-overlay/codex-copilot-launcher/src/setup.rs:188-216`, `codex/codex-rs-overlay/codex-copilot-launcher/src/setup.rs:222-267`). Return `shell::get_shell(ShellType::Bash, Some(&path))` so the existing shell type detection and `derive_exec_args` path stays unchanged (`codex/external/repos/codex-patched/codex-rs/core/src/shell.rs:296-310`, `codex/external/repos/codex-patched/codex-rs/core/src/shell.rs:41-52`).

Feature plumbing is already in place. `Config::load` resolves features from `cfg.features` and legacy override sources into a final `features` set (`codex/external/repos/codex-patched/codex-rs/core/src/config/mod.rs:2566-2575`, `codex/external/repos/codex-patched/codex-rs/core/src/config/mod.rs:2622-2630`). The effective `Config` stores that features set in its struct initialization (`codex/external/repos/codex-patched/codex-rs/core/src/config/mod.rs:3578-3591`), and session construction reads `config.features.enabled(...)` already for `Feature::ShellZshFork` (`codex/external/repos/codex-patched/codex-rs/core/src/session/session.rs:840-860`). `FeaturesToml` flattens boolean feature keys, so `-c features.windows_git_bash_shell=true`, `--enable windows_git_bash_shell`, and `/experimental` should all use the standard registry path once the spec exists (`codex/external/repos/codex-patched/codex-rs/features/src/lib.rs:619-628`, `codex/external/repos/codex-patched/codex-rs/features/src/lib.rs:630-654`).

Conflict surface: moderate but clean. `core/src/shell.rs` and `core/src/session/session.rs` are upstream-hot paths, but the code change can be additive and small: a new detector module plus a 2-4 line branch at the existing default-shell decision. Avoid changing the generic `get_bash_shell()`/`get_shell_path()` ordering because those are cross-platform shell semantics and would risk unintended WSL/PATH behavior. The fork requirement for upstream-canonical edits means the session branch and any new core module should carry `// SANDBOX PATCH:` markers, and `codex/docs/implementation/patch-surface.md` should get a §14 invariant and §15 replant note for the feature/default-off gate and Git-for-Windows-first detector (`codex/CLAUDE.md:16-24`).

## G4 recommendation and scoped change outline

Recommendation: **fresh minimal implementation**, reusing the old detector logic rather than cherry-picking the old commits. The old commits are valuable source material, but they targeted the launcher-era first-run `default_shell` config and `features.unified_exec=false` interaction (`1d828e5947:codex-rs/codex-copilot-launcher/src/config.rs:55-98`, `fff065934c:codex-rs/codex-copilot-launcher/src/config.rs:76-84`). Current launcher code already retains explicit `default_shell` and forcibly enables unified exec for Copilot sessions (`codex/codex-rs-overlay/codex-copilot-launcher/src/config.rs:91-108`), while the missing behavior is a core default when no explicit override exists (`codex/external/repos/codex-patched/codex-rs/core/src/session/session.rs:840-860`). A direct cherry-pick would mostly touch stale launcher concerns and would not install the requested default-off codex experimental feature at the modern core seam.

Concrete follow-up scope:

1. `codex/external/repos/codex-patched/codex-rs/features/src/lib.rs`: add `Feature::WindowsGitBashShell` and a default-off visible `FeatureSpec` with key `windows_git_bash_shell`, matching the `LegacyPasteBurstHeuristic`/`UserMessageStyling` staging pattern (`codex/external/repos/codex-patched/codex-rs/features/src/lib.rs:137-145`, `codex/external/repos/codex-patched/codex-rs/features/src/lib.rs:1005-1030`).
2. `codex/external/repos/codex-patched/codex-rs/core/src/windows_git_bash.rs` (new, `#[cfg(windows)]`) plus a non-Windows no-op or cfg-gated call site: implement the Git-for-Windows-first detector from the launcher (`codex/codex-rs-overlay/codex-copilot-launcher/src/setup.rs:188-216`, `codex/codex-rs-overlay/codex-copilot-launcher/src/setup.rs:222-267`).
3. `codex/external/repos/codex-patched/codex-rs/core/src/session/session.rs`: in the default shell selection, after `ShellZshFork` and before `shell::default_user_shell()`, if `config.features.enabled(Feature::WindowsGitBashShell)` and detector returns a Bash shell, use that; otherwise fall back to current PowerShell behavior (`codex/external/repos/codex-patched/codex-rs/core/src/session/session.rs:840-860`).
4. Tests: add focused unit tests for the detector candidate ordering (modeled after the current launcher `where_git_to_bash_resolves_cmd_layout` test at `codex/codex-rs-overlay/codex-copilot-launcher/src/setup.rs:318-350`) and a session/default-shell selection test proving feature off -> PowerShell/default path and feature on + detected Git Bash -> Bash.
5. Docs/registry: add `// SANDBOX PATCH:` markers at the enum/spec/session branch and a new `codex/docs/implementation/patch-surface.md` row/invariant. Do not edit the inner smaller registry unless the team decides it should mirror wrapper patch-surface rows; current shell-selection evidence lives only in the wrapper registry.

Open design questions for planning:

- Should the feature auto-detect Git Bash only, or also allow a feature-specific config path? Today users can already set a fully explicit shell through launcher `default_shell` (`codex/codex-rs-overlay/codex-copilot-launcher/src/config.rs:63-70`, `codex/codex-rs-overlay/codex-copilot-launcher/src/config.rs:106-108`), so the minimal feature should probably auto-detect and let explicit `default_shell` remain the custom-path escape hatch.
- Should a failed feature-on detection emit a startup warning, or silently fall back to PowerShell? The current shell default silently falls back through PowerShell/cmd (`codex/external/repos/codex-patched/codex-rs/core/src/shell.rs:252-286`), but a visible experimental feature may be easier to debug if it warns when enabled and Git Bash is not found.
- Should Windows shell tool descriptions change when this feature is on? Current Windows shell-command guidance says "Runs a Powershell command" (`codex/external/repos/codex-patched/codex-rs/core/src/tools/handlers/shell_spec.rs:181-196`), while the actual default would become Bash under the feature. If descriptions are static at process compile-time, updating them dynamically may be higher scope than the shell-selection behavior itself.
