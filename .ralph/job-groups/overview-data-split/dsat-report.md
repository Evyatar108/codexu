## Recommendations

1. **`<plugin_root>/lib/sync_job_statuses.sh`**: fix Windows jq quoting by passing the status payload via `--argjson` or a heredoc-piped filter file, and add a smoke-test invoked from `skills/parallel-ralph/SKILL.md` Step 5 that round-trips a known status through the helper before the first scheduling tick. Today the silent-failure mode required operator intervention.

2. **`<plugin_root>/skills/review-changes/SKILL.md`**: capture `pre-fixer-SHA` before Round 1 of each Phase 5 sub-phase (5a/5b/5c) and pin Round 2 / Phase 5b / Phase 5c diffs to that SHA. Three of the four "clean" review outcomes in this run were vacuous-clean because the fixer commits had already merged into `main` before the next review fired. Mechanically remove the possibility that "empty findings" means "we reviewed an empty diff."

3. **`<plugin_root>/skills/review-plan-with-ralph/SKILL.md`**: add a verification step requiring that every numeric acceptance-criterion count (`N tasks`, `N rows`, `N files`) be re-greped against the canonical source during plan review. The "51 tasks" drift slipped through 9 plan-review iterations and surfaced as overrides in 3 jobs plus a Copilot false-positive in code review. The cost of one extra `git grep -c` call is negligible against the rework cost.

4. **`<plugin_root>/skills/decompose-plan/SKILL.md`**: add a cross-member invariant for documentation jobs that follow porting jobs. If member J writes a SKILL.md / docs example referencing a schema produced by member K, J's acceptance criteria must include `grep -E '<field-name>' <data-file>` proving each documented field exists on at least one live entry. Three of the four Claude-sourced High findings in this run stemmed from skill-rewrite documenting an aspirational schema absent from the live data file.

5. **`<plugin_root>/prompts/claude.md`** (and the Codex iteration prompt): for any AC containing the verbs "render", "rerender", "preserve state", or "reload", require evidence that exercises the path under a state change (e.g., open two details -> rerender -> still open AND scope chips still present), not just an initial-load pass. Copilot's F-010 (rerender drops enrichments) was a real correctness bug that the iteration agent's verifiedEvidence had passed because the AC only checked first-load.

6. **`<plugin_root>/agents/criteria-validator.md`**: teach the validator to flag any acceptance criterion that asserts a numeric count without naming the exact grep / DOM-count command that produces the number. This run's "51 task entries" survived plan review precisely because the count and the verification command were separated — fix that coupling at criteria-validation time.
