### Codebase Architecture

`plugins\ralph-overview` is a Claude Code plugin with Node 20+ / TypeScript workspaces:

- `bin\ralph-overview.mjs` is the consumer-facing dispatcher for `sync`, `watch`, `dev`, `build`, `mcp`, `install-server`, and `cli`.
- `tools\overview-mcp\src\` is the MCP server using `@modelcontextprotocol/sdk`, Zod schemas, Vitest tests, and TypeScript `NodeNext`.
- `tools\overview-viewer\src\` is the React 19 + Vite 8 dashboard.
- `scripts\sync-ralph-state.mjs` and `scripts\lib\*.mjs` generate snapshots, sidecars, recommendations, activity logs, and watcher output.
- `templates\overview-data.template.js` and `templates\overview-config.template.json` are the current consumer scaffolding sources.
- `skills\work-on`, `skills\triage`, and `skills\blocker-report` show the current slash-skill pattern.

The plugin already uses `.mcp.json` for plugin MCP registration and `launch.cjs` for build-on-first-launch caching.

### Technical Constraints

- Do not add consumer-specific defaults to production code; templates may be generic only.
- Consumer root must flow through `OVERVIEW_REPO_ROOT`; plugin root through `RALPH_OVERVIEW_PLUGIN_ROOT`.
- Consumer entry should go through `bin\ralph-overview.mjs`, not internal script paths.
- `overview-data.js` must remain plain JS assigning `window.OVERVIEW_DATA`; comments and rich UI blocks must be preserved.
- Config array merge replaces defaults, so scaffolded `watcher.ignored` must include all broad ignore patterns from `scripts\lib\default-config.mjs`.
- Existing tests around `install-server.ts` appear stale: they expect `settings.local.json` and `codexu-overview`, while current source writes `settings.json` and `ralph-overview`.
- `loadConfig()` warns on missing Ralph subdirs and assumes config shape; `overview.init` should not depend on successful preexisting config loading.
- Use `atomicWriteFile`; do not hand-roll JSON writes.
- MCP operational tools should spawn via the dispatcher, as `sync-now` and `dev-server-start` already do.
