## Issue: Tunnel authentication gate is missing entirely
**File:** packages/happy-server/sources/app/api/api.ts:78-80
**Severity:** Critical
**Problem:** The new `authenticateTunnel` decorator (line 78-80) simply sets `request.userId = tofuConfig.localUserId` without performing ANY verification that the request came through the Dev Tunnels gateway. While the plan states "Microsoft Dev Tunnels gateway's `X-Tunnel-Authorization` becomes the sole identity gate," the server code never checks for or validates this header. The gateway consumes and strips `X-Tunnel-Authorization` before forwarding, meaning the server has no way to distinguish between a legitimate tunnel-admitted request and an arbitrary HTTP request from anyone who can reach the port.
**Evidence:** The diff shows the complete removal of all claim verification logic (old lines 81-90) and replacement with a trivial `request.userId = tofuConfig.localUserId` assignment. There is no check for any header, no validation of gateway admission, no authentication at all for tunnel requests.
**Suggested fix:** The architecture relies on network-level isolation (the Dev Tunnels gateway only forwards authorized requests to the backend port).
