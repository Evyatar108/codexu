**Technical Constraints**

Do not put `name`, `description`, or `nickname_candidates` in `explorer.toml`. Built-ins are loaded as raw `ConfigToml`, unlike user role files, so metadata fields would be unknown config keys.

The smallest safe TOML shape is a comment header plus:

```toml
developer_instructions = """..."""
```

A TOML comment header can cite inspiration, for example `# Inspired by the design of Claude Code's built-in Explore subagent; prose rewritten for codex.`

Runtime read-only enforcement is not currently guaranteed by role TOML alone. Spawn code applies the role, then `apply_spawn_agent_runtime_overrides()` copies the parent turn’s permission profile afterward in `core/src/tools/handlers/multi_agents_common.rs`. So the practical implementation should preserve the read-only behavior contract in the prompt unless the plan expands to spawn-order/permission changes.

`codex exec` does not expose a direct `--agent-type explorer` flag. The smoke test should run `codex exec` normally and prompt the parent agent to call `spawn_agent` with `agent_type: "explorer"` against a small target.

The codexu worktree is dirty with unrelated Happy files and a modified `codex` submodule pointer; implementation must use a separate codex worktree and avoid reverting unrelated changes.
