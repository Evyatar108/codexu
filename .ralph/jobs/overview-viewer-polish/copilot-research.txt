**Grounded research:** the feature belongs almost entirely in `tools/overview-viewer/`, with `plans/overview-data.js` staying read-only as the data contract and `plans/overview.html` remaining a generated artifact.

### Codebase Architecture

- **Monorepo / build:** PNPM workspace, with `tools/overview-viewer` registered in **both** `pnpm-workspace.yaml` and root `package.json`. Root scripts expose `pnpm overview`, `pnpm overview:build`, and `pnpm overview:build:preview`.
- **Viewer package:** `tools/overview-viewer/` is **TypeScript + React + Vite**. Docs mention React 18, but the authoritative dependency is `tools/overview-viewer/package.json`, which pins **React 19.2.0** / `react-dom` 19.2.0, Vite 8, and `vite-plugin-singlefile`.
- **Entry/build flow:** `tools/overview-viewer/overview.html` is the Vite entry, `src/main.tsx` mounts `src/App.tsx`, and `vite.config.ts` inlines `plans/overview-data.js` into the built `plans/overview.html` while preserving `file://` compatibility.
- **Data model:** `src/types.ts` mirrors `window.OVERVIEW_DATA` from `plans/overview-data.js`: `tasks`, `phaseTree`, `runs`, `periodic`, `cadence`, `lastTouched`, `effort`, `risk`, `workstream`, `sizeBucket`, `spawnedFrom`.
- **Renderer organization:**
  - `src/components/` — UI surfaces (`Kanban`, `CommandList`, `TaskCommand`, `Toolbar`, `TodayPanel`, `PhaseTree`, etc.)
  - `src/hooks/` — local UI state (`usePersistentExpanded`, `useMultiAxisFilter`, `useHashNav`, `useWhatsNewSinceLastVisit`, `useBulkSelection`)
  - `src/utils/` — pure helpers (`taskClassification`, `kanbanOrdering`, `clipboard`, `warnings`, `commandNavigation`, etc.)
- **Tests:** `vitest.config.ts` runs in **`environment: 'node'`**. Current tests are mostly SSR/static-markup oriented, not browser-interaction heavy.

### Technical Constraints

- **Do not mutate data from the viewer:** `plans/overview-data.js` is hand-edited source of truth; renderer changes stay in `tools/overview-viewer/src/`.
- **Preserve build model:** `vite.config.ts` hard-codes the fetch-and-re-execute HMR path and single-file static build. No async/module replacement for `window.OVERVIEW_DATA`.
- **Preserve existing intentional deviations:** README/CLAUDE call out:
  1. phase-tree `deferred` derivation,
  2. blocked/paused rows pushed to bucket tail,
  3. `lastTouchedAt` ascending within bucket.
- **CSS ordering is currently load-bearing:** `src/styles.css` uses `data-cmd-status` + `data-task-status` for global row ordering. Phase D must replace that with explicit DOM buckets, not layer a second ordering system on top.
- **Interactive controls inside `<summary>` must stop propagation:** relevant to quick actions and any Radix checkbox/button work.
- **`activateWorkstream()` in `App.tsx` imperatively opens `.toolbar-filters`**. If filters move to Radix Popover, that path must become state-driven.
- **Bucket nesting affects navigation/persistence:** current hash-nav only expands task rows, not parent buckets; current persistence only knows task ids.
- **Tests are Node/SSR-oriented:** browser-only parsing/focus/outside-click logic is harder to verify without changing the harness.

### Implementation Suggestions

- **Phase A/B:** keep changes in the current architecture.
  - Add search highlighting in `TaskCommand.tsx`, but use a helper that can transform `descriptionHtml` **without touching `<code>`** and without relying on browser-only DOM APIs in render.
  - Put copy-success state at the `App.tsx` level (singleton toast) and pass callbacks into `TaskCommand.tsx`; reuse existing `.copy-btn.copied`.
  - Extend `commandNavigation.ts` for flash behavior; current smooth scroll already exists.
  - Add the global reduced-motion block and toolbar elevation in `src/styles.css`, near existing toolbar and target-highlight rules.
- **Phase C:** use Radix only where the seed suggests.
  - Good rollout order is exactly what the seed proposes: tooltip first, then dialog, then toolbar filter popover, then checkbox.
  - Keep native `<details>` for sections and command rows; that matches current CSS and persistence patterns.
- **Phase D:** `CommandList.tsx` is the natural home.
  - Group tasks in JS, reuse `sortTasksByLastTouchedAsc()` **within** each emitted bucket, and move blocked-tail CSS under bucket scope.
  - Extend `usePersistentExpanded.ts` with bucket-prefixed keys under the existing v2 object.
  - Add stable ids to top-level sections for the ToC.
  - Reuse `filterBucketForTask()` plus an extracted `recentRuns()` helper for sticky-frame metrics.
- **Phase E:** promote `Layout` from `<main>` to a real shell.
  - Create a left rail component and move `TodayPanel`, what’s-new, recently shipped, periodic due-soon, and `Legend` there.
  - Keep Kanban/commands/roadmap/parallelism/deps in the main column.
  - Add responsive collapse at the shell/layout layer, not ad hoc inside each child.
