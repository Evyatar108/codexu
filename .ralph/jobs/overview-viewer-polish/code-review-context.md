# Code Review Context — overview-viewer-polish (Round 1, code scope)

Patterns and codebase conventions discovered during review. These complement the structured findings in `code-review-findings.json`.

## Established conventions reinforced by this batch

- **Single App-owned toast pipeline.** All copy buttons (`CopyNameButton`, `CopyCommandButton`, `QuickCopyButton`, `BulkCopyButton`) route through `copyTextWithToast(...)` (`src/utils/copyFeedback.ts`) which calls `writeClipboard` and dispatches via the lifted `useToast()` instance owned by `App.tsx`. The `.copied` class is locally tracked per button via `useCopiedFeedback`. Future copy affordances should reuse this path; do not call `writeClipboard` directly from a button component.
- **Hash navigation pipeline.** Command-row jumps go through `navigateToCommand(taskId, expandTask)`; this sets `window.location.hash`, expands the row, calls `scrollIntoView({block: 'center', behavior: 'smooth'})`, and applies the shared `cmd-flash` pulse via `flashCommandElement` (uses a `WeakMap<element, timerId>` to coalesce repeated flashes). `useHashNav` deliberately re-implements the same body inline rather than delegating to `navigateToCommand` so the hash itself is not rewritten on initial mount (avoids history churn). The kanban quick-action however does **not** route through this helper (see F-006) — inconsistent.
- **Density preference state.** `useDensity()` owns the row-density toggle, persists `'comfortable' | 'compact'` under `codexu-overview-density-v1`, and toggles `body.classList` for the `compact` selector. Read/write helpers are pure functions accepting a `Pick<Storage, ...>` so they remain testable under vitest `environment: 'node'`. New compact-mode styling should hang off `body.compact` rather than introducing a second density store.
- **Split-projects vitest harness.** `vitest.config.ts` now defines two projects: `ssr` (Node, react-dom/server, excludes `interactions/**`) and `interactions` (jsdom, Testing Library + user-event). Phase C interaction stories (Tooltip, Dialog) added their tests under `src/__tests__/interactions/`. All preexisting SSR tests stayed in the `ssr` project untouched — option (a) from the plan was taken successfully. Future Radix/jsdom-only ACs belong under `interactions/`.
- **Build-side sidecar minification.** `vite.config.ts` now minifies `plans/overview-data.js` via esbuild during the singleFile inline pass, but **only inside the static build** — the source data file stays readable and the dev server still serves the unminified sidecar. This was added retroactively after US-010 first exceeded 500 KB; treat it as part of the bundle-gate infrastructure now.

## Gotchas / surprises

- **Phase buckets ≠ raw `task.phase`.** `CommandList.countVisibleTasksByOrderBucket` consumes `orderBucketForTask(task)` returning `'brainstorm' | 'inprogress' | 'ready' | 'shipped' | 'closed'` (mapped via `PHASE_TO_ORDER_BUCKET`), NOT the raw `task.phase` strings like `closed`, `plan-ready`, `shipped`. Future Phase D work (US-015 bucket headers) must use `orderBucket` IDs in DOM (`cmd-bucket-<orderBucket>`).
- **`escapeHtml` is duplicated.** A 4-character escape helper lives inline in `TaskCommand.tsx:54-61` only — `searchHighlighting.ts` does NOT escape match text before wrapping. Today this is safe because `applyTextHighlight` only runs on text-between-tags, but if the match text reaches the wrap with `<`/`>`/`&` already in it (e.g. matching across an HTML entity boundary), the output becomes structurally fragile. See F-007.
- **Global `prefers-reduced-motion` guard is CSS-only.** `styles.css:33-38` zeros `animation` and `transition` for `*` with `!important`. This degrades every CSS animation correctly (US-006). But JS-driven scrolls (`scrollIntoView({behavior: 'smooth'})`) and JS-driven timers (the 1.5s `cmd-flash` removal) do not consult `matchMedia('(prefers-reduced-motion: reduce)')`. Future motion guards must also gate JS code paths, not rely on CSS alone. See F-002.
- **`KeyboardHelp` is the only Radix surface landed.** `FilterChips` is still a native `<details className="toolbar-filters">` because US-012 was blocked by the bundle gate. `activateWorkstream` at `App.tsx:71-75` and `setAllDetails` at `App.tsx:63-69` still touch `HTMLDetailsElement.open` directly — these paths are intentionally unchanged. The `<details>` sweep also still toggles command rows (`<details className=\"cmd\">`) and the bucket-less command section wrapper (`<details className=\"section sec-cmds\">`).
- **Quick-actions visibility transitions reset on focus loss.** Hidden behind `opacity: 0; visibility: hidden;` with `transition: opacity 0.12s, visibility 0.12s` — both target the same hover/focus-within rule on `.cmd > summary`. Verified hidden by default, revealed on hover/focus, with the transition disabled under `prefers-reduced-motion: reduce` via the global guard.
