## Correctness

**[High]** Search highlighting may double-escape already-escaped HTML entities
**File:** `tools/overview-viewer/src/utils/searchHighlighting.ts:15-57`
**Severity:** High
**Problem:** `highlightMatches` wraps matches in `<mark>` tags but does not HTML-escape the matched text before wrapping. If the input `html` contains user-controlled search query that matches a literal `<` or `>` in the HTML (e.g., in a task description), the resulting `<mark>${match}</mark>` could inject unescaped angle brackets.
**Evidence:** Line 18 creates `applyTextHighlight` that does `text.replace(matcher, (match) => <mark class="search-match">${match}</mark>`)` with no HTML escaping of `match`. The function correctly skips `<code>` blocks and tags, but `match` itself is never escaped.
**Suggested fix:** Change line 18 to `return text.replace(matcher, (match) => <mark class="search-match">${escapeHtml(match)}</mark>)` where `escapeHtml` is the existing utility at `TaskCommand.tsx:75-82`.
