## Architect Analysis

### US-001 — end-to-end data flow

- `/implement-with-ralph` Phase 1 today has no `--target-repo` arg (SKILL.md lines 23-43).
- The target-repo decision is currently made by `convert-to-ralph-prd` Step 1 via an Explore agent over plan/research/PRD text (SKILL.md lines 246-283), then written into `prd.json.repoDir` (line 283).
- `worktree-create.mjs` already accepts and uses `--target-repo` (lines 16-23, 60-65, 95-113, 142-173).

### US-001 — validation placement

**Most defensive: both layers.**
- Eager parse-time validation in `implement-with-ralph` Phase 1 (fail fast before any work).
- Hard validation in `convert-to-ralph-prd` Step 1 before any writes (defends against direct skill invocation that bypasses the parent).
- Use `git -C <path> rev-parse --show-toplevel` as the validation primitive — both Codex and Copilot research agree on this.

**Worktree-of-a-different-main-repo behavior:** `git rev-parse --show-toplevel` returns the worktree root (not the main repo's canonical storage root). This is acceptable for `prd.json.repoDir` consumers because the PRD wants the actual editable repo root, not the main repo's `.git` storage root.

### US-001 — skip semantics / lost side effects

Skipping the Explore agent in `convert-to-ralph-prd` Step 1 loses:
- the plan-file/research-brief scan,
- the interactive confirmation branch,
- the notepad log side effect (SKILL.md lines 277-283).

There is **no separate cluster/scope side effect in Step 1 today**; the real loss is repo-detection guidance, not scope analysis. Skipping is safe when the operator/lead has authoritatively decided the target via `--target-repo`.

### US-001 — precedence

Flag wins over plan inference. Downstream code that assumes plan-analysis-derived repo:
- `convert-to-ralph-prd` Step 1 itself (SKILL.md lines 264-283),
- `worktree-create.mjs` callers (lines 16-23, 60-65),
- `prd.json.repoDir` consumers.

Handoff contract: if `--target-repo` is present, bypass the Explore agent and propagate the resolved absolute path directly through Step 1 → Step 5 → Step 8.

### US-001 — regression guard

Smallest "absent flag → unchanged" test: keep the existing target-repo inference test and add one assertion that when no flag is passed, Step 1 still calls the Explore path and writes the same `repoDir`. Extend the existing `convert-to-ralph-prd` smoke/regression suite (referenced by plugin AGENTS.md lines 25-30, 38-40).

### US-002 — placeholder convention

Use noun placeholders with angle brackets, no repo names in prose:
- `<wrapper-repo>` — the outer repo (e.g., codexu) that holds the submodule as a pointer.
- `<submodule>` — the inner repo whose code is being edited.
- `<submodule-remotes>` — the set of remotes the submodule must be pushed to.
- `<submodule-main>` — the submodule's main branch (typically `main`).
- `<wrapper-main>` — the wrapper's main branch.
- `<consumer-machine>` — any machine that has the wrapper installed and consumes the plugin via `copilot plugin update` or equivalent.

### US-002 — Phase 6 handoff trigger

Trigger condition: `prd.json.repoDir` is a submodule under the lead's wrapper repo.

**Cheapest detection:** check if `prd.json.repoDir` is reachable as a submodule path from `repo_root` using:


Returns non-empty + exit 0 → it IS a submodule → emit the ship ceremony handoff prose in the Phase 6 kind=done block.
