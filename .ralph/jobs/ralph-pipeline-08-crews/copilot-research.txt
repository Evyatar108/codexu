### Codebase Architecture

This is a pnpm monorepo with a React/Vite roadmap dashboard under `tools\overview-viewer` and Node ESM sync scripts under `scripts\lib`. Ralph state is generated into `plans\overview-ralph-state.{js,json}` plus agent artifacts like `plans\overview-snapshot.json`.

### Feature-Relevant Code

- `scripts\lib\sync-core.mjs`: central state derivation. `walkRalphState()` reads `.ralph` bundles, `assembleStateFromBundles()` maps them to `byTaskId`, `mergeAndWrite()` merges watcher updates, `writeSidecar()` emits all durable artifacts.

### Technical Constraints

The watcher is currently slug-oriented; `.crews` manifest changes do not naturally map to a Ralph bundle slug. Crew events likely need a full recompute path or a new “crew-state changed” update mode rather than forcing them through `deriveAffectedTaskUpdate()`.

Explicit-vs-heuristic conflict resolution needs persistence: `walkRalphState()` currently rebuilds from `.ralph` only and does not receive prior sidecar state, so explicit crew entries must be read from the prior snapshot/sidecar and merged after heuristic discovery.

I could not inspect `D:\ai-developer-toolkit\plugins\crews\...` due permission denial, so the exact `/spawn-member` runtime contract should be verified during implementation.
