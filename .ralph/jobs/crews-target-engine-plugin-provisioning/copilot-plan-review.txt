### Feasibility

[High] `buildVerdict` defines `currentThreadUsable = !restartRequired`, which makes failed installs report `currentThreadUsable: true` because `restartRequired` is false for `status:"failed"`. That contradicts the load-bearing restart/respawn verdict in the plan: a blocked member still cannot use a plugin after a failed install. Update the verdict semantics and AC8 to assert failed verdicts do not imply usability.

[High] The plan does not specify a plugin-name-to-source-path mapping for marketplace plugins whose install name differs from their directory. `ralph-orchestration` lives at `plugins/ralph` (`plugins/ralph/.claude-plugin/plugin.json`), not `plugins/ralph-orchestration`, while AC7 requires `list-plugins` to report sourceVersion for `ralph-orchestration`. `source.js` should read the marketplace index `source.path` or carry an explicit mapping, and tests should cover this case.

### Completeness

[Medium] `install-plugin` auth is left as an open question, but the command is mutating global/user plugin state. Existing operator-trust commands such as `hooks/commands/spawn-member.js` use `cli auth: open` plus an explicit handler-side `--as <lead>` / `resolveActorRole(...) === 'lead'` check. The plan should make that mandatory and add command tests for non-lead or missing `--as` rejection.

[Medium] The plan says the generated `/crews-install-plugin` skill “wraps the CLI,” but current generation behavior differs by engine: Claude generated skills can describe CLI fallback, while Copilot generated skills under `.copilot-plugin/copilot-skills/*/SKILL.md` are slash-intercept oriented and explicitly say not to rerun side effects. Clarify whether the required surface is slash-command execution only or actual Skill-tool CLI fallback, then adjust `scripts/gen-skills.js` or the wording/tests accordingly.
