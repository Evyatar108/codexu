### Codebase Architecture

This repo is a JS/TS monorepo with a Rust `codex` submodule. `packages\happy-cli` is a Node/TypeScript CLI using `pnpm`, `tsc`, `pkgroll`, and Vitest. Codex engine code lives under `codex\external\repos\codex-patched\codex-rs`, a Rust workspace using `cargo`/`just`.

Happy’s Codex path is app-server based: `packages\happy-cli\src\codex\codexAppServerClient.ts` spawns or reattaches to `codex app-server`, while `packages\happy-cli\src\codex\runCodex.ts` owns the Happy session, `MessageQueue2`, and event forwarding to the app.

### Technical Constraints

The feature must stay opt-in at two layers: Codex feature config and Happy setting. LOW-A should use only Codex’s existing input queue wake; LOW-B must not run simultaneously or duplicate completion turns.

The active-turn race is real: watcher wake returns while a later turn is active, and `on_task_finished()` only applies `MaybeContinueIfIdle` after clearing active state. A feature-gated `maybe_start_turn_for_pending_work().await` immediately after that idle transition is the minimal seam.

Codex fork rules require every upstream-canonical edit in `codex-rs` to carry `// SANDBOX PATCH:` and update `codex\docs\implementation\patch-surface.md`.
