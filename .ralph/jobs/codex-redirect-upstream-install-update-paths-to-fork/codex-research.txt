**Technical Constraints**

- `gim-home/codex` is internal, so unauthenticated `curl https://api.github.com/repos/gim-home/codex/releases/latest` may return 404. Current doctor `http_get_json` has no auth plumbing, so the plan should accept a warning or add explicit `gh`/token support.
- Fork tags look like `v0.135.0-copilot-api.1`, not `rust-v...`. Both doctor and TUI tag parsing currently expect `rust-v`.
- `parse_version` in doctor and TUI only handles plain `major.minor.patch`; the `-copilot-api.N` suffix will make update comparison return `None` unless parsing is extended.
- `UpdateAction::command_args()` returns static command/args. The primary `gh release download v<VERSION>` flow needs a dynamic version, so it does not fit the existing API without broadening it. The static GitHub Packages command is easier to fit, but needs registry/auth setup.
- There is no fork Homebrew cask. The Homebrew probe should be removed or converted to a non-network warning, not redirected.
- TUI update code is release-only via `#![cfg(not(debug_assertions))]`, and snapshots will need updates if visible strings change.
- Any new inline edits in upstream-canonical files must be marked and registered in patch-surface plus audits.

**Implementation Suggestions**

Use inline `// SANDBOX PATCH:` edits, not a new overlay constants crate. These are network-suppression patches, and an overlay would still require call-site edits while adding dependency conflict surface.

Recommended story split:

1. Doctor updates: patch `cli/src/doctor/updates.rs` to use `https://api.github.com/repos/gim-home/codex/releases/latest`, strip `v`, stop calling Homebrew, and update labels to fork install/update text. Add unit tests for fork tag parsing and labels. Also patch the `cli/src/doctor.rs` remediation string.

2. Unix daemon updater: rewrite `install_latest_standalone()` to early-return `Ok(())` with a marker, removing the remote script execution and now-unused imports. Patch `ensure_managed_codex_bin` to point to the fork install docs/commands.

3. Hint strings and latent TUI: update `tui/src/update_action.rs`, `tui/src/history_cell/notices.rs`, `tui/src/update_prompt.rs`, `tui/src/npm_registry.rs`, `tui/src/updates.rs`, `tui/src/update_versions.rs`, and affected snapshots/tests if the operator confirms literal “EVERY” includes dead update UI.

4. Cross-cutting audit: add new `KNOWN_PATCH_FILES` entries for `cli/src/doctor/updates.rs`, `app-server-daemon/src/update_loop.rs`, `app-server-daemon/src/lib.rs`, and any TUI files touched. Extend `ENDPOINT_PATTERNS` for `chatgpt.com/codex/install`, `@openai/codex`, and Homebrew update references.
