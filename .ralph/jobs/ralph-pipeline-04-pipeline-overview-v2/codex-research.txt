**Codebase Architecture**
The relevant area is the codexu overview dashboard, not the Happy app packages. It is a pnpm monorepo with a React/Vite dashboard in `tools/overview-viewer/` and Node ESM sync scripts in `scripts/lib/`.

Key pieces:

- `tools/overview-viewer/`: React 19 + TypeScript + Vite single-file build. Dev command is `pnpm overview`; static artifact is generated by `pnpm overview:build` into `plans/overview.html`.
- `plans/overview-data.js`: hand-edited source-of-truth global, loaded as `window.OVERVIEW_DATA`.
- `plans/overview-ralph-state.js/json`: generated Ralph sidecar, loaded as `window.OVERVIEW_RALPH_STATE`.
- `scripts/lib/sync-core.mjs`: Ralph filesystem scan, task matching, sidecar writes, Plan 05 artifact emission.
- `scripts/lib/watch-ralph-state.mjs`: chokidar watcher used by `pnpm sync-ralph-state:watch` and the Vite plugin.
- `tools/overview-viewer/vite.config.ts`: serves/inlines `overview-data.js` and `overview-ralph-state.js`, and starts the shared Ralph watcher during `pnpm overview`.

Tests are split: `scripts/lib/**/*.test.mjs` run from root Vitest in Node, while overview UI tests run via `tools/overview-viewer/vitest.config.ts` with SSR and jsdom interaction projects.

**Feature-Relevant Code**
Main integration points:

- `tools/overview-viewer/src/App.tsx`: top-level composition. Natural place to insert `<PipelineOverview>` between `Toolbar` and `Kanban`.
- `tools/overview-viewer/src/hooks/useMultiAxisFilter.ts`: already returns `filters`, `setFilters`, `toggleFilter`, `visibleTaskIds`, and `visibleKanbanTaskIds`.
- `tools/overview-viewer/src/utils/filters.ts`: defines `ActiveFilters`, `cloneFilters()`, and `ralphStage` filtering for command + kanban surfaces.
- `tools/overview-viewer/src/components/Toolbar.tsx`: hardcoded 10 Ralph stage chips and existing chip styling/state pattern.
- `tools/overview-viewer/src/components/RalphStageChip.tsx`: stage class naming and tooltip conventions.
- `tools/overview-viewer/src/types.ts`: already has `RalphStage`, `OverviewRalphState`, `Snapshot.runDurations`, and minimal Plan 05 stubs for `Recommendation`/`DependencyGraph`.
- `scripts/lib/sync-core.mjs`: currently reads PRDs inside `readJobLikeBundles()`, assembles `byTaskId` in `assembleStateFromBundles()`, exports `atomicWriteFile()`, and emits Plan 05 artifacts from `writeSidecar()`.
- `scripts/sync-ralph-state.mjs`: one-shot path calls `walkRalphState()` then `writeSidecar()`.
- `scripts/lib/watch-ralph-state.mjs`: watcher cold-start calls `writeSidecar()`; debounced updates call `mergeAndWrite()`.

Current main does not have `scripts/lib/score-recommendations.mjs`, `scripts/lib/derive-dependency-graph.mjs`, `plans/overview-recommendations.json`, or `plans/overview-dependency-graph.json`.

**Technical Constraints**
`runDurations` already belongs on `Snapshot`, not `OverviewRalphState`. Current `writeSidecar()` passes `state.runDurations ?? {}` into `buildSnapshot()`, but no code computes it yet. Do not persist `runDurations` in `overview-ralph-state.json`.

`atomicWriteFile()` is already exported from `scripts/lib/sync-core.mjs`; reuse it.

The current Plan 05 `Recommendation` type is stale/minimal: `{ taskId?, score?, rationale? }`. Plan 04 wants `{ taskId, score, stage, reasons: string[] }`, so update `types.ts` and `emit-snapshot-schema.mjs` together.

Config currently lacks `recommendations`, `outputs.recommendationsJson`, and `outputs.dependencyGraphJson` in `.ralph/overview-config.json`, schema, `default-config.mjs`, `default-config.d.mts`, and `resolve-config.mjs`.

`OverviewData.spawnedFrom` is a top-level map, not an `OverviewTask` field. Add only `OverviewTask.blocks?: string[]` and possibly `priority?: number`.

`overview.html` is already 501,307 bytes, so any “under 500 KB” criterion is ambiguous unless defined as `<512000`.

**Implementation Suggestions**
Add pure modules first: `score-recommendations.mjs` and `derive-dependency-graph.mjs`, with adjacent `.d.mts` and root Vitest tests. Feed both with a non-persisted `prdsByTaskId` carrier derived while `assembleStateFromBundles()` still has matched bundles and parsed PRDs.

Refactor sync emission so derived artifacts happen after the sidecar write in both paths. Concretely, avoid burying Plan 04 scoring inside UI code or duplicating atomic writes. Use a helper from `sync-core.mjs` that receives `{ state, overviewData, prdsByTaskId, config }`, writes recommendations and dependency graph via `atomicWriteFile()`, then builds the Plan 05 snapshot with those fresh values plus computed `runDurations`.

For the UI, create `PipelineOverview.tsx` with a fixed `RalphStage[]` order matching `Toolbar.tsx`. Count `ralphState.byTaskId` stages, render 10 buttons, and use:

`setFilters(current => { const next = cloneFilters(current); next.ralphStage = active ? new Set() : new Set([stage]); return next })`

Put jsdom click tests under `tools/overview-viewer/src/__tests__/interactions/`.

For downstream cascade, implement a small script/helper or explicit sync step that scans `.ralph/jobs/*/job-state.json` and `.ralph/job-groups/*/job-state.json` for `status: "RUNNING"` with `orchestrator.terminal !== true`. If any peer jobs are active, append entries under `## Deferred Cascade` in the Plan 04 job `notepad.md`; otherwise update plans 06/07/08/09/12 and `plans/ralph-pipeline-INDEX.md`.
