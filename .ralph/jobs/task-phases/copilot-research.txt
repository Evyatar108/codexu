   A task may appear in:
   - command row
   - kanban card
   - `roadmap-data` JSON maps
   - `parallel-assignments.md` status table

5. **Maintenance docs currently describe the old schema.**

## Implementation Suggestions

The natural integration point is to keep this as a **bookkeeping-layer change inside `plans/overview.html`**, not a data extraction. I’d recommend the plan frame the implementation as:

1. **Introduce explicit per-task phase metadata on the HTML rows**  
   Add `data-phase`, `data-status`, and optional `data-plan-only`, `data-plan-source`, job-id/artifact attrs to each `<details class="cmd">`. This matches the source doc’s “HTML-only” scope better than inventing a new sidecar schema.

2. **Treat the badge as a renderer, not the source of truth**  
   Refactor `classifyAndOrderCmds()`, `classifyCmd()`, Today panel logic, and toolbar filtering to derive from phase + modifier instead of legacy badge classes. Keep legacy `b-ready`/`b-blocked`/`b-paused`/`b-closed` as fail-soft aliases.

3. **Keep the 3-column kanban**  
   The source doc’s recommendation matches the current UI structure. Phase should become a pill on each card; blocked/paused should be a secondary modifier pill.

4. **Update all existing task rows explicitly**  
   Because there is no central task model, migration is manual and should be called out as such in the plan. The plan should preserve the source doc’s operator-confirmed migration table for `plan-review` vs `brainstorm-ready`.

5. **Document the model in markdown, with `parallel-assignments.md` as the enum home**  
   `codexu-roadmap.md` should add only the standing-rule summary and link out.

6. **Reference the current maintenance skill as prior art**  
   Reuse `.agents/skills/roadmap-and-overview/SKILL.md` as the description of the current data model and note it as a likely follow-up/staleness risk.

For the full PRD conversion, the strongest story decomposition is:
- **Story 1:** phase/status schema + `overview.html` renderer/plumbing
- **Story 2:** migrate all existing tasks/cards/command rows
- **Story 3:** document conventions in `parallel-assignments.md` and `codexu-roadmap.md`
- **Story 4:** smoke representative progression paths + legacy-class fail-soft behavior
