**Codebase Architecture**

`ralph-overview` is a Node/TypeScript plugin with three main runtime surfaces:

- Root ESM scripts under `scripts/` and `scripts/lib/`: sync watcher, derivation, snapshots, recommendations, data loading, and data mutation.
- MCP workspace under `tools/overview-mcp/`: TypeScript MCP server, built with `tsc`, using `@modelcontextprotocol/sdk`, `zod`, and imports back into `scripts/lib`.
- Viewer workspace under `tools/overview-viewer/`: React 19 + Vite 8 dashboard, TypeScript, Vitest/jsdom tests.

Build/test is driven by root [package.json](<D:/harness-efforts/codexu/ai-developer-toolkit/plugins/ralph-overview/package.json>) with `npm run test:lib`, `npm run test:viewer`, `npm run typecheck`. Plugin release version is in `.claude-plugin/plugin.json`, `.github/plugin/plugin.json`, and `.codex-plugin/plugin.json`, currently `2.13.0`; root package version is just a private workspace wrapper.

**Technical Constraints**

- Preserve the two-axis model: `OverviewTask.lifecycle` is bookkeeper state; `RalphPipelineState.stage` is watcher state.
- Unknown lifecycle must remain actionable: a `byTaskId` entry absent from `overviewData.tasks` should not be excluded.
- Use `classifyShard(task) === 'cold'` in Node-side `scripts/lib` code instead of duplicating `merged`/`archived` sets.
- Do not import `scripts/lib/data-store.mjs` into browser code: it imports `node:fs`, so the viewer needs a browser-safe mirror/helper, likely in `tools/overview-viewer/src/utils/taskAliases.ts`.
- No new dependencies are needed.
- First test run should tee output to a file per repo convention.

**Implementation Suggestions**

Add a small cold-task predicate in `scripts/lib/score-recommendations.mjs` using `classifyShard(tasksById.get(taskId)) === 'cold'`, and filter `Object.entries(byTaskId)` before scoring. Because `classifyShard(undefined)` resolves hot, missing `overviewData.tasks` entries will still appear.

Fix unblock at the source: import `classifyShard` in `scripts/lib/unblock-candidates.mjs` and return non-candidate when the blocked task itself is cold. Do this inside `computeUnblockCandidate`, not only `findUnblockCandidates`, because `emit-snapshot.mjs` calls `computeUnblockCandidate` directly and MCP `overview.unblock_candidates` later reads snapshot task flags.

Mirror the blocked-task cold check in `tools/overview-viewer/src/utils/unblockCandidates.ts`, using a browser-safe alias-mapped lifecycle helper. Add tests in `score-recommendations.test.mjs`, plus a focused `emit-snapshot.test.mjs` or `unblock-candidates.test.mjs` case, and viewer tests for no NOTIFY on merged/archived blocked tasks.
