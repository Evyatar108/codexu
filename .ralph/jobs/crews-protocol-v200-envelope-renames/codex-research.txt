**Technical Constraints**

`CREWS_STRICT_SCHEMA=1` and `CREWS_STRICT_ENVELOPE=1` are enabled by default in the test runner, so schema changes must be atomic with tests. Production is warn-only unless strict env vars are set.

The canonical schema is code, not JSON Schema. Update `PAYLOAD_RULES`, `CANONICAL_ADDRESSES`, `validateFromSubfields()`, and `validatePayloadRules()` together.

A pure rename is not enough: if `from.kind` remains allowed as an unknown extra field, stale rows can still pass. Add explicit stale-field rejection for `from.kind` and `payload.replyToId` in strict validation.

**Implementation Suggestions**

Use one bundled `v3.0.0` breaking ship, not split releases. The external consumer count is effectively zero; the affected surface is concentrated in crews tests/docs plus codexu backlog text. A deprecated alias period would preserve the confusing dual names and weaken the schema tests.

Update docs atomically: `docs/protocol.md`, `CHANGELOG.md`, `AGENTS.md`, and the local gitignored `CLAUDE.md` if present. I did not find a `CLAUDE.md` in the crews checkout.

Migration tests should assert both positive and negative shape: every emitter writes `from.routingKind` and never `from.kind`; member-reply writes `payload.replyTo` and never `payload.replyToId`; strict validation rejects old names.
