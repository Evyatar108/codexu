### Codebase Architecture

The relevant code lives in `ai-developer-toolkit\plugins\ralph-overview`, an ESM Node plugin with npm workspaces:

- `bin\ralph-overview.mjs` — plugin dispatcher for `init|sync|watch|dev|build|mcp|install-server|cli`.
- `scripts\init-consumer.mjs` — shared init engine used by CLI and MCP.
- `scripts\lib\*.mjs` — sync/config/snapshot/command derivation logic.
- `tools\overview-mcp` — TypeScript MCP server and Vitest tests.
- `tools\overview-viewer` — React 19 + Vite 8 dashboard.
- `templates\*.json` — emitted consumer scaffolds.
- `skills\` and `.copilot-plugin\copilot-skills\` — Claude/Copilot guided skills.

The consumer-side precedent is `bin\ralph-overview.mjs` in codexu, with package scripts in root `package.json`.

### Technical Constraints

- The generated wrapper must be self-contained; it cannot import plugin code before locating the plugin.
- Existing config loading tolerates unknown keys in `.ralph-overview\config.json`, but the wrapper cannot reuse `loadConfig()` unless it has already found the plugin. It should implement a minimal JSON read for wrapper-specific config keys.
- `overview.init` currently does **not** emit package scripts by default. The feature goal implies a behavior change, so CLI/MCP/docs/tests must align.
- Semver comparison should be implemented inline or with no runtime dependency in the template.
- Marketplace release requires synchronized version updates in:
  - `plugins\ralph-overview\.claude-plugin\plugin.json`
  - `.claude-plugin\marketplace.json`
  - `.github\plugin\marketplace.json`
  - `.agents\plugins\marketplace.json`
  - codexu `AGENTS.md` active plugin table
  - `CHANGELOG.md`
