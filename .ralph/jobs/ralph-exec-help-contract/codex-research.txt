**Technical Constraints**
Use the existing usage strings exactly; do not author new copy.

Help must short-circuit before required argument validation. Otherwise `--help` will still fail on missing `--prompt` / `--output`.

Help must also short-circuit before side effects:

- `codex-exec.mjs`: no prompt read, no stdin assembly, no `codex` spawn.
- `copilot-exec.mjs`: no temp dir, no output file open/truncate, no `copilot` spawn.

Do not disturb exact negative stderr fixtures. Existing tests pin unknown-argument and missing-argument output, so `--unknown`, no args, bad effort, and missing files must keep current behavior.

Ralph is ESM and dependency-free here. Use `node:test` and `node:assert/strict`; no new test framework.

**Implementation Suggestions**
Implement this as a narrow parser/main change in both wrappers:

- Add `const stdout = opts.stdout ?? process.stdout;` in each `main`.
- Add a `help` / `showHelp` flag in each parsed config.
- In `parseArgs`, handle `--help` and probably `-h` for consistency with other v5.46 ports.
- Skip validation when help is set.
- In `main`, after parsing, write `usage()` / `USAGE` to stdout and return `0`.

For tests, add one focused test per wrapper in the existing test files. Assert:

- exit code is `0`
- stdout contains `Usage:` and is non-empty
- stderr is empty
- spawn is not called
