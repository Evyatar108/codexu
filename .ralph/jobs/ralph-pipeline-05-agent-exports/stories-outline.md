# Stories Outline: Plan 05 — Agent-readable exports

*Preliminary decomposition from `/plan-with-ralph --improve --autonomous`. Feed to `/implement-with-ralph --from-plan` for PRD generation.*

## US-001: Build `emit-snapshot.mjs` pure function

**Description:** As an agent consuming pipeline state, I want a single `Snapshot` JSON to read so that I have everything (tasks + pipeline state + optional recommendations/dependencyGraph/runDurations) in one file.
**Acceptance Criteria:**
- [ ] `scripts/lib/emit-snapshot.mjs` exports `buildSnapshot({ ralphState, overviewData, recommendations, dependencyGraph, generatedFromCommit })` returning a `Snapshot`.
- [ ] When `recommendations` / `dependencyGraph` / `runDurations` inputs are absent, `Snapshot.recommendations === []`, `Snapshot.dependencyGraph === { nodes: [], edges: [] }`, `Snapshot.runDurations === {}`.
- [ ] `snapshotVersion === 1`.
- [ ] `Snapshot.tasks[i]` merges `OverviewTask` + (optional) `RalphPipelineState` under `ralph`.
- [ ] Typecheck passes.
**Dependencies:** US-006 (types).
**Estimated complexity:** small

## US-002: Build `emit-activity.mjs` append + rotate

**Description:** As an operator, I want a tail-able append-only log of stage / progress events so that I can answer "what just changed?" without reparsing the whole snapshot.
**Acceptance Criteria:**
- [ ] `scripts/lib/emit-activity.mjs` exports `appendActivity(repoRoot, event, { activityPath, activityBackupPath, maxLines = 1000 })` and `rotateActivity(activityPath, activityBackupPath)`.
- [ ] Append opens the file in append mode, writes a single `writeSync(JSON.stringify(event) + '\n')`, calls `fsyncSync`, closes.
- [ ] Before append, rotation: if the file has ≥ `maxLines`, rename to `activityBackupPath` (overwriting any prior backup), then start fresh.
- [ ] Lines fit within a single 4KB write.
- [ ] Typecheck passes.
**Dependencies:** US-006 (types).
**Estimated complexity:** small

## US-010: Derive `activityEvents` inside `mergeAndWrite`

**Description:** As a downstream activity consumer, I want stage and progress transitions captured without watcher-side prevStateMap plumbing.
**Acceptance Criteria:**
- [ ] `mergeAndWrite` signature unchanged (same `repoRoot`, `config`, `currentState`, `updates`, `generatedFromCommit`).
- [ ] Return value gains `activityEvents: ActivityEvent[]`.
- [ ] Events derived by diffing `currentState.byTaskId` against the new `state.byTaskId` by `taskId`: emits for stage change, `storyCompletion` change (count or fraction), task removal (`newStage: null`), task first-observation (`prevStage: null`).
- [ ] Retain (no diff) emits zero events.
- [ ] Existing callers continue to work without modification.
- [ ] vitest cases for all four diff dimensions in `sync-core.test.mjs`.
- [ ] Typecheck passes.
**Dependencies:** US-006.
**Estimated complexity:** medium

## US-011: Extend `writeSidecar` to emit all durable agent artifacts atomically

**Description:** As a one-shot sync caller, I want a single integration point that emits every Plan 05 artifact.
**Acceptance Criteria:**
- [ ] `writeSidecar` (or a new `emitAgentArtifacts` helper called from inside `writeSidecar`) invokes, in order: schema → snapshot → data-twin → tasks-index. All use `atomicWriteFile`.
- [ ] On first run with no `plans/overview-activity.jsonl` file, the file is created empty (size 0).
- [ ] The watcher does NOT call emitters directly; emission happens once per flush via the same `mergeAndWrite → writeSidecar` path.
- [ ] All writes happen inside the existing lock window.
- [ ] No double-emit.
- [ ] Typecheck passes.
**Dependencies:** US-001..US-005, US-007, US-009, US-010.
**Estimated complexity:** medium

- [ ] Typecheck passes.
**Dependencies:** US-010.
**Estimated complexity:** small

## US-013: Append each activity event inside the lock window

**Description:** As an operator, I want activity log appends to happen atomically under the same lock as the state write so that readers never see torn ordering.
**Acceptance Criteria:**
- [ ] The watcher calls `appendActivity(repoRoot, event)` per event from `result.activityEvents` BEFORE releasing the flush-time lock.
- [ ] If `mergeAndWrite` throws, no appends happen (no phantom events).
- [ ] A new vitest case in `scripts/lib/watch-ralph-state.test.mjs` (file created if absent) verifies lock-hold ordering.
- [ ] Typecheck passes.
**Dependencies:** US-002, US-012.
**Estimated complexity:** small
