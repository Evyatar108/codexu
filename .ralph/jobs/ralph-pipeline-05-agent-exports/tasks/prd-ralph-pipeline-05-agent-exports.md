# PRD: Plan 05 — Agent-readable exports

## Introduction

Turn the data that powers the React dashboard into a clean machine-readable interface for AI agents. An agent starting cold reads ONE file (`plans/overview-snapshot.json`) and has everything it needs — task list, pipeline state, optional recommendations, optional dependency graph, run history. Companion artifacts (`overview-activity.jsonl` for transitions, `tasks/INDEX.md` for human navigation, `overview-snapshot.schema.json` for downstream typing, `overview-data.json` for tools that cannot `eval` JS) round out the surface.

The implementation piggybacks on Plan 02's existing watcher/lock infrastructure. Activity-event derivation happens INSIDE `mergeAndWrite` by diffing `currentState.byTaskId` against the new `state.byTaskId`; no new arguments are added to the signature. The watcher consumes the returned `activityEvents` and appends them after a successful state write, all inside the existing lock window.

## Goals

- Emit `plans/overview-snapshot.json` as the single source of truth for agents.
- Emit companion artifacts: `overview-data.json` (JSON twin), `overview-activity.jsonl` (event log with 1000-line rotation), `overview-snapshot.schema.json` (hand-written JSON Schema v1), `tasks/INDEX.md` (human + agent navigation).
- Update `AGENTS.md` (root) and `tools/overview-viewer/CLAUDE.md` with discoverable pointers.
- Reuse Plan 02's `mergeAndWrite` + `writeSidecar` + lock window; introduce no polling loop.
- Cascade Plan 04 and Plans 06–12 + INDEX to match the shipped artifacts.
- Treat Plan 04 outputs (recommendations, dependency graph, run durations) as conditional inputs — snapshot ships empty containers when Plan 04 has not landed.

## User Stories

### US-001: Build `emit-snapshot.mjs` pure function
**Description:** As an agent consuming pipeline state, I want a single `Snapshot` JSON to read so that I have everything (tasks + pipeline state + optional recommendations/dependencyGraph/runDurations) in one file.

**Acceptance Criteria:**
- [ ] `scripts/lib/emit-snapshot.mjs` exports `buildSnapshot({ ralphState, overviewData, recommendations, dependencyGraph, generatedFromCommit })` returning a `Snapshot`.
- [ ] When `recommendations` / `dependencyGraph` / `runDurations` inputs are absent, `Snapshot.recommendations === []`, `Snapshot.dependencyGraph === { nodes: [], edges: [] }`, `Snapshot.runDurations === {}`.
- [ ] `Snapshot.schemaVersion === 1` (integer).
- [ ] `Snapshot.tasks[i]` merges `OverviewTask` + (optional) `RalphPipelineState` under `ralph`.
- [ ] Typecheck passes.

### US-002: Build `emit-activity.mjs` append + rotate
**Description:** As an operator, I want a tail-able append-only log of stage / progress events so that I can answer "what just changed?" without reparsing the whole snapshot.

**Acceptance Criteria:**
- [ ] `scripts/lib/emit-activity.mjs` exports `appendActivity(repoRoot, event, { activityPath, activityBackupPath, maxLines = 1000 })` and `rotateActivity(activityPath, activityBackupPath)`.
- [ ] Append opens the file in append mode, writes a single `writeSync(JSON.stringify(event) + '\n')`, calls `fsyncSync`, then closes the handle.
- [ ] Before append, rotation: if the file has >= `maxLines`, rename to `activityBackupPath` (overwriting any prior backup), then start fresh.
- [ ] Lines fit within a single 4KB write.
- [ ] Typecheck passes.

## Functional Requirements

- FR-1: `buildSnapshot` is a pure function returning a `Snapshot` with `schemaVersion: 1`.
- FR-2: `Snapshot.recommendations`, `Snapshot.dependencyGraph`, and `Snapshot.runDurations` are always present (empty when source files absent).
- FR-3: `appendActivity` rotates at `maxLines` (default 1000) before writing; uses single `writeSync` + `fsyncSync`.
- FR-4: `mergeAndWrite` diffs `currentState.byTaskId` vs the new `state.byTaskId` and returns `activityEvents` without any signature change.
- FR-5: `writeSidecar` is the single emission point for snapshot/schema/data-twin/tasks-index; all writes use `atomicWriteFile` inside the existing lock window.
- FR-6: The watcher appends activity events ONLY after `mergeAndWrite` resolves successfully and BEFORE releasing the lock.
- FR-7: Config files (`default-config.mjs`, `default-config.d.mts`, `resolve-config.mjs`, `.ralph/overview-config.json`, `.ralph/overview-config.schema.json`) and `tools/overview-viewer/src/__tests__/config.test.ts` all reference the same seven new keys (six scalar paths + one integer).
- FR-8: One-shot `sync-ralph-state` creates `plans/overview-activity.jsonl` empty if absent, but does NOT append activity events outside the watcher path.
- FR-9: `AGENTS.md` agent-pointer documents that activity-log readers must tolerate a final torn line.
- FR-10: The Plan 04 cascade moves `runDurations` from `OverviewRalphState` into `Snapshot`.

## Non-Goals

- Repo-local skills (`/work-on`, `/triage`, `/blocker-report`) — Plan 06.
- React `RecentActivity` sidebar consuming `activity.jsonl` — Plan 07.
- `RalphPipelineState.crewSessions` and crew aggregation — Plan 08.
- MCP server exposing the snapshot — Plan 09.
- Source data edits (`overview-data.js` stays hand-curated; the `.json` is a derived twin).
- `runDurations` population — Plan 04 owns the values; Plan 05 only adds the field to the snapshot type.
- Precise run start/finish event timestamps — descoped to Plan 04 once it adds `createdAt`/`completedAt` to `RalphPipelineState`.
- Auto-generated TypeScript → JSON Schema conversion. Plan 05 ships a hand-written schema for v1.
- Merging to main: all commits land on `ralph-pipeline-05-agent-exports` branch and stay there.

## Design Considerations

- Reuse existing `atomicWriteFile` from `scripts/lib/sync-core.mjs` for all atomic writes.
- Reuse Plan 02's lock window via `acquireLock` / `releaseLock` / `touchLock`. Do NOT introduce a polling loop.
- Co-locate `overview-snapshot.schema.json` with `overview-snapshot.json` in `plans/` for v1 (defer `schemas/` directory extraction to Plan 12).
- Snapshot is derived. Authoring surface stays `overview-data.js` and per-job state files.

## Technical Considerations

- **Plan 02 contract (merged):** `walkRalphState`, `readBundleForSlug`, `assembleStateFromBundles`, `deriveAffectedTaskUpdate`, `mergeAndWrite`, `writeSidecar`, `atomicWriteFile`.
- **Plan 03 coexistence:** Plan 03 owns `tools/overview-viewer/src/utils/filters.ts`. Plan 05 owns additive `tools/overview-viewer/src/types.ts` edits at file end. No collision.
- **Plan 04 conditional:** `plans/overview-recommendations.json` and `plans/overview-dependency-graph.json` are read with `existsSync` checks; falls back to empty defaults when absent.
- **Test runner:** vitest. New tests follow the existing helper pattern in `scripts/lib/sync-core.test.mjs` (`makeTempDir`, `writeJson`, `buildConfig`, `writeOverviewData`, `writeJobState`, `writeGroupState`).
- **TypeScript ambient declarations:** New emitter modules need `.d.mts` companions plus entries in `tools/overview-viewer/src/__tests__/scripts.d.ts`.
- **ajv:** Programmatic ajv import in a vitest test (avoid `ajv-cli`).

- The activity log captures the four diff dimensions (stage, storyCompletion, removal, first observation) and rotates correctly at 1000 lines.

- All five config files plus the config test reference the same seven new keys.

## Open Questions / Assumptions (autonomous-mode inferences)

These are autonomous-mode inferences from the planner. Each should be confirmed during implementation.

1. **Schema co-location vs `schemas/` dir.** Inference: keep at `plans/overview-snapshot.schema.json` for v1.
2. **`tasks/INDEX.md` JSON twin.** Inference: do NOT add `tasks/INDEX.json`; the snapshot already is the machine-readable twin.
3. **`ajv` strategy.** Inference: use a vitest test that imports ajv programmatically (per F-008); do NOT rely on `ajv-cli`.
4. **Activity event for `action: 'retain'`.** Inference: no event for retain (retain produces no `byTaskId` diff).
5. **`storyCompletion` event.** Inference: emit when count or fraction changes; `changedFields: ['storyCompletion']`.
6. **Run start/finish.** Inference: descope precise run timestamps to Plan 04; Plan 05 approximates via stage entry/exit.
7. **One-shot mode emits artifacts.** Inference: one-shot sync creates the activity file empty if absent but does not append events.
8. **Config-key naming.** Inference: six scalar paths + one integer `activityMaxLines` (no nested object under `activity`).
