**Technical Constraints**
Keep `file://` compatibility. Do not fetch JSON; `overview-data.js` must stay a synchronous script global. In Vite dev, `plans/overview-data.js` is outside the package root, so the plugin must explicitly serve/watch it.

The CSS token system in [plans/overview.html](D:/harness-efforts/codexu/plans/overview.html:7) should be ported verbatim, including light-theme overrides and phase badge classes around line 852. No Tailwind/CSS-in-JS.

HTML fragments in data are trusted operator-authored content. Use `dangerouslySetInnerHTML` for `kanbanCards[].html`, `descriptionHtml`, `warnings[].html`, `phaseTree.raw.html`, and `trailingHtml`. Do not derive logic from line endings; current card HTML strings are mixed `\r\n` and `\n`.

React cannot use `style="..."`; `card.inlineStyle` needs a small parser or a controlled ref-based attribute set.

One important parity issue: current “Copy Command” injects scope preambles at copy time via [plans/overview.html](D:/harness-efforts/codexu/plans/overview.html:1770), so it is not byte-for-byte `planPrompt`. The PRD should explicitly decide whether to preserve that behavior or add a separate raw-copy affordance.

`vite-plugin-singlefile` is not currently in the lockfile. `@codexu/overview-viewer` has no package-name collision.

Add focused tests for schema loading, kanban ordering, phase-tree derivation, URL filter parsing, and copy text behavior. Use Playwright or screenshot comparison for static-vs-dev visual parity before replacing [plans/overview.html](D:/harness-efforts/codexu/plans/overview.html:1).
