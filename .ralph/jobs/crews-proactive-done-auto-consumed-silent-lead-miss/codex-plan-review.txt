### Feasibility

- [High] The plan overstates the guarantee from the PID fence. `consumeMailbox` would only reject an orphan after `manifest.lastListenerPid` has been updated to the newer listener PID. If the orphan drains before the newer listener’s `markArmed()` write lands, the manifest still points at the orphan, so the proposed check allows the same silent-loss shape the plan says is eliminated. This is partly acknowledged under “Residual sub-ms window,” but it contradicts the Overview and AC guarantee.
