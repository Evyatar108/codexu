### Codebase Architecture

`packages/happy-cli` is a TypeScript ESM package in a pnpm workspace. It uses strict TS (`packages\happy-cli\tsconfig.json`), Vitest, `pkgroll`, Zod, `cross-spawn`, `ws`, and `ps-list`. Codex-specific code lives under `packages\happy-cli\src\codex\`; command routing is in `packages\happy-cli\src\commands\codexCommand.ts`; global env/path config is centralized in `packages\happy-cli\src\configuration.ts`.

### Technical Constraints

The idle timeout must be a spawn-flag seam only. A TS timer cannot reap the detached orphan because Happy exits while the child survives.

The seam should target one canonical flag spelling, preferably `--idle-timeout <seconds>`, and keep the detection token centralized so changing spelling later is one edit. Probe behavior should mirror `--ws-auth`: run `codex app-server --help`, cache result per `CodexAppServerClient`, emit nothing when unsupported.

RSS must not use `ps-list.memory`; existing tests and docs explicitly treat that as `%mem`, not RSS KB, and unsupported on Windows. Either implement a real platform-aware sampler, or keep RSS `null` on unsupported platforms.

Sidecar schema is `.strict()` and append-only; do not rename existing snake_case fields. Doctor/status must stay read-only and retain exit-code behavior.

### Implementation Suggestions

Use a structured CLI opt-in, not only `--codex-arg`: add `extractCodexIdleTimeoutFlag()` in `cliArgs.ts`, parse integer seconds, pass through `handleCodexCommand()` → `runCodex()` → `CodexAppServerClientOptions`. Apply only to WS app-server spawning; stdio should not receive the idle-timeout seam unless explicitly decided later.

In `codexAppServerClient.ts`, add `isIdleTimeoutAvailable()` and `getIdleTimeoutAvailability()` mirroring `isWsAuthAvailable()`. When configured and supported, append `[IDLE_TIMEOUT_FLAG, String(seconds)]` before `extraAppServerArgs`; when unsupported, no-op with a one-time non-error log.

For doctor, add an explicit idle/orphan-age column or summary buckets using existing disconnect/exit telemetry. Recommended buckets: `<1h`, `1-24h`, `>24h`, plus “never-disconnected/unknown”. Keep per-instance values too, because they are easiest to verify in tests.

For RSS, introduce a small platform-aware sampler module used by both `refreshLastSampledRssKb()` and `probeCodexDaemon()`. If Windows support is not cheap via a reliable true-RSS source, scope Windows to `null`.

Defer `kill-idle` unless the plan can reuse discovery enumeration plus per-cwd locks and confirm-dead-before-delete without exposing private `CodexAppServerClient` methods or adding broad cross-cwd termination plumbing.
