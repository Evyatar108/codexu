**Codebase Architecture**
The relevant code is a React/TypeScript Vite app, not Svelte. The viewer lives under `tools/overview-viewer/` and is packaged as `@codexu/overview-viewer` with React 19, Vite 8, Vitest, Testing Library, and Radix Tooltip/Dialog.

Key structure:

- `tools/overview-viewer/src/App.tsx` owns top-level data loading, HMR reload of `window.OVERVIEW_DATA`, filter state, and layout.
- `tools/overview-viewer/src/components/` contains `TaskCommand.tsx`, `CommandList.tsx`, `Kanban.tsx`, `Toolbar.tsx`.
- `tools/overview-viewer/src/utils/filters.ts` owns `FilterAxis`, `ActiveFilters`, `matchesTaskFilter`, `matchesKanbanFilter`, `getTaskSearchHaystack`.
- `tools/overview-viewer/src/hooks/useMultiAxisFilter.ts` computes visible command and kanban task IDs.
- `tools/overview-viewer/vite.config.ts` serves `plans/overview-data.js`, watches it, emits `overview-data:update`, and inlines it into `plans/overview.html`.
- `scripts/lib/sync-core.mjs` already writes `plans/overview-ralph-state.{js,json}`.
- `tools/overview-viewer/src/types.ts` already defines `RalphStage`, `RalphPipelineState`, `OverviewRalphState`, and `getOverviewRalphState()`.

`plans/overview.html` is generated. Do not hand-edit it; rebuild through `pnpm overview:build`.

**Technical Constraints**
The plan should correct “Svelte component” to React TSX. There is no Svelte stack in this viewer.

The sidecar must be synchronously available before React mounts. Serving `/overview-ralph-state.js` in Vite is insufficient unless `tools/overview-viewer/overview.html` includes the script tag and `vite.config.ts` inlines that tag during static build.

Plan 02 conflict boundary needs tightening. `plans/ralph-pipeline-02-watcher.md` explicitly says not to also watch `plans/overview-ralph-state.js` in the Vite plugin, because Plan 02’s watcher emits `overview-ralph-state:update` directly. Plan 03 should only add dev middleware for `/overview-ralph-state.js` and static-build inlining. Do not add `server.watcher.add(overviewRalphStatePath)` in Plan 03.

Radix Tooltip tests that require hover/focus belong under `src/__tests__/interactions/`, because the default test project is node SSR and excludes interaction tests.

The static budget is tight: current `plans/overview.html` is about `495245` bytes, and the Ralph sidecar is about `3352` bytes. If “under 500KB” means 500,000 bytes, Plan 03 has very little room. Acceptance criteria should define the exact threshold and verify with `wc -c plans/overview.html`.

**Implementation Suggestions**
Update Plan 03’s decomposition around these integration points:

2. Thread state as `App.tsx -> useMultiAxisFilter(data, taskIdFilter, ralphState)` and `App.tsx -> CommandList ralphState -> TaskCommand -> RalphStageChip`. `Toolbar` does not need `ralphState`.

5. Update all call sites/tests, including `urlFilter.test.ts`.
