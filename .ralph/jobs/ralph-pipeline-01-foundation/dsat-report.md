## Recommendations

1. **`skills/analyze-iteration/SKILL.md` — Manifest Verifier and Refactoring Pass degraded-mode handling.** When Agent-spawn is unavailable, do not silently fall back to "synthesize inline" for 7 iterations. Either (a) emit a single up-front "verifier unavailable for this run — Quality Gate cannot fully attest" banner into `dashboard.md` and refuse to record Quality Gate PASS, or (b) record `analysis-result.json.summary.manifestVerifier.unavailable: true` and surface it in the orchestrator post-run summary so the human reviewer knows the safeguard was bypassed. The current behavior (advisory-only warning, fail-open PASS) makes the safeguard invisible.

2. **`skills/review-plan-with-ralph/SKILL.md` — soft-cap policy.** The plan-review loop exited at iter 8 with 11 Mediums still open, and the subsequent code-review then re-discovered three of them (parse-error semantics, deep-freeze, derived-field provenance) as code-review findings. Either (a) require zero open Mediums in the Completeness category before exit, or (b) when the loop exits with open Mediums, automatically inject them into the affected stories' acceptance criteria so the iteration agent encounters them before code-review does. Today they are dropped on the floor.

3. **`prompts/claude.md` (and codex iteration prompt equivalent) — cascade-refresh enumeration.** The US-007 iteration agent missed 4 of 9 sibling plans because the AC said "sibling plans referenced in the Hand-off section" without enumerating them. Add iteration-agent guidance: when a story's ACs mention "cascade refresh", "sibling plans", or "downstream plans", enumerate the full set via `ls plans/` (or glob), grep each for the changed contracts, and verify exhaustively. Alternatively, change the plan-author template (`skills/ralph-orchestration/...plan-with-ralph...`) to require an explicit checklist of cascade-refresh targets in such stories.

4. **`skills/review-changes/SKILL.md` — re-review reviewer coverage.** Re-review round 2 ran Claude only (Codex and Copilot `skipped`). Either document this as intentional (cost-savings) in the skill prose, or ensure regression rounds re-invoke all configured reviewers. The F-003 regression was caught by Claude alone this time, but single-reviewer regression rounds have lower coverage by design.

5. **`skills/review-changes/SKILL.md` — `main...HEAD` diff fallback.** When `worktree.external=true` and `branch.created=false` (job runs directly on main), `git diff main...HEAD` is empty and the docs reviewer had to work around it via grep. Read `job-state.json.startCommit` and use `git diff <startCommit>..HEAD` as the canonical scope so the reviewer always sees the job's actual changeset.

6. **`skills/analyze-iteration/SKILL.md` Refactoring Pass.** Same Agent-spawn root cause as recommendation 1. Add a deterministic fallback: when Agent-spawn is unavailable at a refactor trigger, the iteration agent can still run a structural cross-file duplication grep (e.g., `grep -rn "function" scripts/lib/*.mjs | sort | uniq -c`) and write a stub report, instead of recording "skipped — no Agent-spawn".
