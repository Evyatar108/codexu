### Technical Constraints

`plans/overview-data.js` is explicitly hand-curated and must not be written by sync code. This is documented in `tools/overview-viewer/CLAUDE.md`.

The overview app depends on synchronous global sidecars. Static build currently inlines only `<script src="./overview-data.js"></script>` from `tools/overview-viewer/overview.html`; future Ralph UI work must preserve that model.

`tools/overview-viewer/tsconfig.json` has `allowJs: false`, `strict: true`, `moduleResolution: "bundler"`, and `include: ["src", "vite.config.ts"]`. A TS test that statically imports `../../../../scripts/lib/derive-ralph-stage.mjs` may need an ambient declaration or typed dynamic import to satisfy typecheck.

Current `.gitignore` ignores only `.ralph/**/worktree/`, not `.ralph/overview-config.local.json`. If the plan requires local config to be gitignored, add that ignore rule.

The config examples are `.json` but include JSONC-style comments/header-comment language. If using `JSON.parse`, committed config and local config must be pure JSON. Otherwise the resolver needs an explicit JSONC parser, which would add dependency/scope.

`rg` is unavailable in this environment, but that only affects implementation ergonomics.

### Implementation Suggestions

Use a small Node ESM script stack:

- `scripts/lib/default-config.mjs`: plain object defaults.
- `scripts/lib/resolve-config.mjs`: deep merge defaults, committed config, local config; resolve paths to absolute paths; freeze result.
- `scripts/lib/derive-ralph-stage.mjs`: pure predicate, no filesystem/config.
- `scripts/lib/sync-core.mjs`: parse `plans/overview-data.js`, walk configured `.ralph` subdirs, derive per-task state, write JS+JSON sidecars atomically.
- `scripts/sync-ralph-state.mjs`: CLI wrapper only.

For parsing `overview-data.js`, reuse the existing trusted sidecar execution pattern from `src/__tests__/testData.ts`: execute with a controlled `window` object and read `window.OVERVIEW_DATA`. That avoids brittle string parsing.

For deterministic idempotency, sort discovered jobs/groups/brainstorms by slug before processing, sort unmatched entries before writing, and compute duplicate winners using `updatedAt` plus slug as a tie-breaker.

For review counts, keep missing file as `undefined`; only count open `Critical|High|Medium` findings when the file exists and parses.

Add a focused unit test for `deriveRalphStage`. Because of the `.mjs` import/typecheck constraint, consider a tiny declaration file under `tools/overview-viewer/src/__tests__/scripts.d.ts` or use dynamic import with an explicit local function type.
