**Codebase Architecture**

Target code is the `ai-developer-toolkit` submodule, specifically [plugins/crews](D:/harness-efforts/codexu/ai-developer-toolkit/plugins/crews). It is a plain Node/CommonJS plugin, not an npm package; there is no `plugins/crews/package.json`. Main structure:

- `hooks/`: engine hook entrypoints and shared runtime state code.
- `hooks/config.js`: compatibility re-export hub for paths, locks, mailbox, actors.
- `hooks/locks.js`: file-lock primitives.
- `hooks/safe-io.js`: atomic JSON write + Defender/AV retry logic.
- `hooks/actors.js`: actor manifest CRUD, heartbeat/listener state writes, process helpers.
- `hooks/mailbox.js`: mailbox/outbox JSON and JSONL operations.
- `lib/listener-loop.js`: long-running listener heartbeat/delivery loop.
- `tools/`: CLI wrappers such as `crews.js`, `spawn-member.js`, `review-mail.js`.
- `skills/`: generated/user-facing command skill docs.
- `tests/`: custom worker-thread runner, invoked from toolkit root as `node plugins/crews/tests/run.js`.
- `.claude-plugin/`, `.codex-plugin/`, `.github/plugin/`: Claude, Codex, and Copilot plugin manifests/hooks.

Versioning is centralized through [scripts/bump-version.js](D:/harness-efforts/codexu/ai-developer-toolkit/plugins/crews/scripts/bump-version.js:14), which updates three plugin manifests, three marketplace indexes, and [tests/version.test.js](D:/harness-efforts/codexu/ai-developer-toolkit/plugins/crews/tests/version.test.js:4).

**Technical Constraints**

Do not globally shrink `safe-io` retry defaults; comments explicitly tie the 6.5s budget to Windows Defender resilience. Hook paths need deadline-scoped behavior, while heartbeat keeps full AV resilience.

Be careful with “rename outside lock.” Releasing the manifest lock after computing a new manifest but before the final rename can lose concurrent updates unless a generation/CAS scheme is added. A safer first implementation is: no multi-attempt rename retry while holding manifest lock for hook-context writes; fail open/log cheaply on transient exhaustion, and retry on a later hook.

Dead-holder stealing should not import `health.js` directly from `locks.js` without checking cycles: `health.js` imports `actors.js`, `actors.js`/`config.js` already depend on locks. Prefer a small leaf liveness helper or a local conservative helper returning `true|false|null`.

Heartbeat separation must preserve v3.6.2 `lastListenerEpoch` semantics. Initial arm still needs a manifest-locked epoch/PID update; recurring heartbeat ticks should write a small heartbeat stamp outside the manifest hot lock and `deriveListenerState()` should read that stamp as primary/fallback.

Tests should use existing seams: `safe-io` already supports `sleepFn`, and tests already monkey-patch `fs.renameSync`. Timing-sensitive lock/listener tests belong in the `DEFAULT_SERIAL_DENYLIST` in [tests/run.js](D:/harness-efforts/codexu/ai-developer-toolkit/plugins/crews/tests/run.js:39).

**Implementation Suggestions**

Center the plan on L3:

1. Add host-scoped dead-holder lock stealing in `locks.js`: read pid/hostname/acquiredAt; if hostname matches local host and pid is definitively dead, steal immediately under the existing `.steal` mutex. Keep age/future timestamp fallback for foreign host, invalid pid, unknown liveness, corrupt/empty locks.
2. Add hook-context write options through `safe-io.js`, `mailbox.writeJsonAtomic()`, `actors.writeManifest()/updateManifest()`, and selected hook call sites. In hook context, avoid retrying the 6.5s rename budget under manifest lock; fail open where hooks already tolerate best-effort state.
3. Split heartbeat into a tiny per-actor heartbeat file/stamp. Update `touchHeartbeat()`, `listener-loop`, `actor-state.deriveListenerState()`, and health/list display readers to use it while preserving manifest epoch ownership.
4. Coalesce manifest writes by skipping `updateManifest()` when a patch is a no-op. Moving heartbeat out of the manifest will remove the largest recurring write.
5. Replace full transcript reads with a shared bounded tail reader for `turn-observability.js` and `detect-active-bg.js`.
6. Apply L2 timeout mitigation by changing only PreToolUse/PostToolUse/Stop in Claude and Codex hook manifests to 30s. Leave Copilot unchanged.
7. Add docs for Defender exclusions for workspace `.crews/`, likely in `README.md` and `AGENTS.md`.

Recommended bundle decision: ship this hot-lock/starvation fix here. Do not bundle the separate attached-shell idle reap fix; this work addresses heartbeat starvation, not the separate runtime reaping mechanism noted in the feature request.
