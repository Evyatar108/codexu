**Technical Constraints**

The audit must begin with version resolution. Current local plugin working trees are not trustworthy for this feature because they are stale/dirty. Record `git rev-parse origin/main`, plugin manifest versions, `copilot --version`, and `node --version`.

This cannot be proved by unit tests alone. The core claims depend on Copilot’s actual hook payloads, slash-command equivalent behavior, plugin loading, MCP discovery, and Windows process spawning. Targeted tests are useful supporting evidence, but the report needs real Copilot sessions.

Windows behavior is load-bearing. Ralph’s v5.45.1 fix is specifically `shell: true` for `codex`/`copilot` shim spawning, so the audit should run on Windows, not only POSIX.

Ralph-overview has a known MCP registration limitation under Copilot CLI `1.0.55`: plugin-manifest MCP discovery may fail while codexu workspace `.mcp.json` fallback succeeds. Treat these as separate checks.

**Implementation Suggestions**

Use a four-story audit plan: crews, ralph, ralph-overview, then report aggregation.

Start with preflight: create/use an isolated toolkit worktree at `origin/main`, verify versions, verify installed Copilot plugin source/cache, and capture environment versions in `.ralph/jobs/plugins-copilot-cross-engine-audit/audit-report.md`.

For crews, use a disposable crew/state cwd. First inspect generated launcher with no-launch/static mode if available, then run a real Copilot lead/member session to exercise SessionStart, PreToolUse listener arm, Stop listener gate, PostToolUse nag, command dispatch, kind-tag parsing, and resume via `COPILOT_AGENT_SESSION_ID`.

For ralph, run generator parity checks, then execute minimal Copilot-driven `/plan-with-ralph` and `/implement-with-ralph` jobs with `--pause-after 1` or equivalent tiny scope. Specifically verify `src/ralph.mjs`, `src/review-loop.mjs`, `src/codex-exec.mjs`, and `src/copilot-exec.mjs` are the actual invoked paths.

For ralph-overview, verify both workspace `.mcp.json` fallback and plugin-manifest MCP registration separately. Check `overview.parallel_ready_tasks`, `overview.watcher_status`, `.ralph/overview-watcher.owner`, and snapshot freshness after MCP boot.

Recommendation gate: do not migrate the bookkeeper lead to Copilot until crews and ralph pass end-to-end, and ralph-overview’s MCP path is either verified through Copilot plugin registration or explicitly accepted as workspace `.mcp.json` fallback only.
