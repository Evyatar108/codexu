External survey notes:

- Mozilla sccache docs support Rust via `RUSTC_WRAPPER`, local disk cache via `SCCACHE_DIR`, stats via `sccache --show-stats`, and MSVC/clang support.
- Important caveat: sccache’s Rust key includes parsed rustc arguments. LTO and `RUSTFLAGS=-C debuginfo=0` changes create different cache keys. `CARGO_BUILD_JOBS` should not.
- sccache does not cache crates that invoke the system linker: `bin`, `dylib`, `cdylib`, `proc-macro`. Final `codex`/`codex-core` linking and rusty_v8 link consumption still need measurement.
- Current sampled Tauri workflows use `Swatinem/rust-cache@v2` and `CARGO_PROFILE_DEV_DEBUG=0`, not obvious `RUSTC_WRAPPER` sccache wiring.

**Implementation Suggestions**
Add a wrapper-owned script or documented env block that sets the frozen local iteration profile:

```bash
export PATH="/c/Program Files/LLVM/bin:$PATH"
export RUSTUP_TOOLCHAIN=stable-x86_64-pc-windows-msvc
export CC=clang-cl CXX=clang-cl AR=llvm-lib
export CARGO_TARGET_X86_64_PC_WINDOWS_MSVC_LINKER=lld-link
export CARGO_PROFILE_RELEASE_LTO=off
export CARGO_PROFILE_RELEASE_CODEGEN_UNITS=16
export CARGO_BUILD_JOBS=4
export RUSTFLAGS=
```

Then add optional try-it override:

```bash
export RUSTFLAGS="-C debuginfo=0"
```

For sccache, mirror upstream workflow patterns:

```bash
export SCCACHE_DIR="D:\\sccache\\codex-rs"
export SCCACHE_CACHE_SIZE=50G
wrapper="$(cygpath -w "$(command -v sccache)")"
export RUSTC_WRAPPER="$wrapper"
export CARGO_BUILD_RUSTC_WRAPPER="$wrapper"
sccache --start-server
sccache --zero-stats
```

Verification should explicitly test:

- Same frozen profile, clean `target`, warm sccache: expect high cache hits except linker/bin/proc-macro limits.
- Change only `CARGO_BUILD_JOBS`: expect cache reuse.
- Change LTO or `RUSTFLAGS`: expect misses or separate cache profile; document this as “version the cache/profile,” not normal iteration.
- rusty_v8 archive path present and final binaries build/link with `RUSTY_V8_ARCHIVE`.
- `sccache --show-stats` before/after each run.

For jobs/OOM, script a PowerShell sampler around `cargo build --release --timings ...` and try jobs `4`, then `6`; record wall time, peak commit/RSS from `Get-Process`, and sccache stats. Highest safe value becomes the documented default.

Bundle recommendation: one PR for docs plus helper script/env snippets, because the changes are tightly coupled and wrapper-owned. Keep benchmark results as an appended record; if jobs=6/pagefile findings need machine-specific follow-up, split only that measurement update.
