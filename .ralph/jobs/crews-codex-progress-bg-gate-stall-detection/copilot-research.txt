### Codebase Architecture

`ai-developer-toolkit/plugins/crews/` is a plain Node/CommonJS plugin with no package-level `package.json`, `tsconfig`, or build step. Runtime code is organized around shared hook handlers in `hooks/`, reusable logic in `lib/`, command handlers in `hooks/commands/`, and a custom worker-based test runner at `tests/run.js`.

The plugin supports Claude, Copilot, and codex via engine overlays: `.claude-plugin/plugin.json`, `.github/plugin/plugin.json`, and `.codex-plugin/plugin.json` plus `.codex-plugin/hooks/hooks.json`. Codex hook entrypoints like `hooks/codex-stop.js` translate codex hook stdin through `hooks/codex-shim.js` and then call the shared `hooks/stop.js`.

### Feature-Relevant Code

Key integration points:

- `hooks/stop.js`: existing progress-bg Stop gate is at the “Progress + no-bg gate” block. It imports `detectActiveBg` from `hooks/detect-active-bg.js`, checks `manifest.engine === 'copilot'`, `turnKind === 'progress'`, `state.role === 'member'`, `!isRetry`, and logs `engine=copilot`. A sibling `hooks/detect-active-bg-codex.js` should mirror this API but parse rollout JSONL.
- `hooks/listener-protocol.js`: exports the reusable infra filters. `isCrewsCliInfraCall(cmd)` already handles `$env:CREWS_BIN`; reuse it exactly for codex command filtering.
- `hooks/codex-shim.js`: `codexToClaudeStopInput()` already preserves `transcript_path` and `stop_hook_active`, and threads `last_assistant_message` for report parsing. No new Stop payload plumbing is needed.
- `tests/progress-bg-gate.test.js` and `tests/lib/force-response.js`: existing patterns for detector unit tests and Stop subprocess tests. Add a codex-focused sibling test file rather than overloading the large Copilot test.

### Technical Constraints

Codex rollout parsing is a different transcript schema than Copilot. The detector must correlate `exec_command` `function_call` rows to their `function_call_output` via `call_id` to recover the launching `cmd`, and correlate exits through `await_background_completion` call arguments because terminal text lacks the session id.

The detector should fail toward blocking: unparseable command, stale running signal before the latest `event_msg.task_started`, missing current-turn evidence, or ambiguous session state should produce `nonListenerCount: 0`.

Keep behavior unchanged for Claude/Copilot. Copilot’s detector and retry skip should remain byte-compatible except for engine-aware log text. Version updates must use `plugins/crews/scripts/bump-version.js`.

### Implementation Suggestions

Add `hooks/detect-active-bg-codex.js` with small pure helpers: read rollout JSONL, find last `event_msg.task_started` boundary, index `exec_command` calls by `call_id`, map backgrounded `"Process running with session ID N"` outputs to session ids, map `await_background_completion` calls to `session_id`, and mark sessions dead on terminal output.
