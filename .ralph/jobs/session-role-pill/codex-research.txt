**Codebase Architecture**

This is a pnpm monorepo with `packages/happy-app`, `happy-cli`, `happy-server`, `happy-wire`, etc. The target is `packages/happy-app`, a TypeScript React Native/Expo app using Expo Router, Zustand storage, Unistyles theming, and Vitest with `react-test-renderer`.

Session list data is normalized before UI render:

`Session` metadata lives in [storageTypes.ts](D:/harness-efforts/codexu/packages/happy-app/sources/sync/storageTypes.ts:8), including `currentModelCode`, `currentPermissionModeCode`, and `flavor`.

`buildSessionRowData()` in [storage.ts](D:/harness-efforts/codexu/packages/happy-app/sources/sync/storage.ts:109) creates `SessionRowData`, which is what list rows receive. It currently includes `flavor`, but not `currentModelCode` or `currentPermissionModeCode`.

`SessionsList` renders inactive session rows through `SessionItem` in [SessionsList.tsx](D:/harness-efforts/codexu/packages/happy-app/sources/components/SessionsList.tsx:342). Active sessions use a separate compact path in [ActiveSessionsGroupCompact.tsx](D:/harness-efforts/codexu/packages/happy-app/sources/components/ActiveSessionsGroupCompact.tsx:422).

**Technical Constraints**

`SessionRowData` is intentionally “all primitives, cheap to deep-equal” in [storage.ts](D:/harness-efforts/codexu/packages/happy-app/sources/sync/storage.ts:83). Keep added row fields primitive strings/nulls.

`useSessionListViewData()` uses deep equality in [storage.ts](D:/harness-efforts/codexu/packages/happy-app/sources/sync/storage.ts:1485). Adding the metadata fields to `SessionRowData` is required so metadata-only updates can notify the list.

Do not add these fields to `keyExtractor`; row identity should remain `session-${session.id}`.

Be careful using `modelModeOptions` for permission resolution: Codex hardcoded modes do not include `plan`, but the acceptance case uses `flavor='codex'` plus `currentPermissionModeCode='plan'`. The row should render raw metadata codes, not filter through flavor-specific available modes.

`SessionItem` is currently not exported, so a direct snapshot test needs either a named export or a small exported subcomponent. Existing component tests mock RN modules and use `react-test-renderer`.
