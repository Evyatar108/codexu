### Technical Constraints

- `shell:true` is intentional for Windows `.cmd` shim resolution; AGENTS.md says not to copy it broadly, but it is valid for `codex-exec.mjs` and `copilot-exec.mjs`.
- Codex result output must remain owned by Codex’s `-o <outputFile>` argument. Captured stdout should go to a **sidecar**, not replace `--output`.
- The wrapper currently has no explicit `jobId`/lens id argument. Sidecar placement must be derivable from `--output` or added via a narrow optional flag such as `--sidecar-dir`. Deriving `dirname(outputFile)/lenses/` is the least invasive default.
- Existing tests pin exact stderr text and argv shape; changing stdio/env/timeout behavior will require test updates.
- `RUST_LOG` should be merged into `env` without mutating the caller’s `process.env`; preserve caller overrides where sensible, or document precedence.
- Windows process snapshotting needs to account for `shell:true`: the child PID is likely the shell wrapper, not necessarily `codex.exe`. Tree-kill should target the spawned PID with `/T`; process/TCP snapshots may need PowerShell/CIM queries for descendants.
- Broad silent catches are discouraged by repo rules. If `taskkill` or snapshot commands fail, record the failure in the sidecar rather than ignoring it as success.
