**Technical Constraints**
The latch shape and signature format are documented in `member-crash-notifications.js`: `{ memberCrash: { [leadName]: { [memberName]: signature } } }`.

`appendSystemMailbox()` in [mailbox.js](D:/harness-efforts/codexu/.ralph/jobs/crews-liveness-notifications-lock-contention-hook-errored/worktree/plan/ai-developer-toolkit/plugins/crews/hooks/mailbox.js:544) does schema validation and takes the recipient mailbox lock. The crash path must preserve append-before-latch-write: latch persistence only after mailbox append succeeds.

Do not raise the latch timeout. That would make hook hot paths wait longer. The right fix is reducing lock duration.

Moving the scan outside the latch lock is safe for the latch invariant because the latch lock never protected manifests, process health, or ownership. Those are already snapshot reads. For stronger race resistance, revalidate only final candidates before appending; that keeps lock cost proportional to notify candidates, not all members.

**Implementation Suggestions**
Use approach 1 as the primary fix: split sweep into two phases.

1. Outside the latch lock, collect crash candidates:
   - `listNames`
   - `readManifest`
   - six skip guards
   - `getMemberHealth`
   - `buildDeadSignature`
   - candidate payload construction

2. Inside `withStateFileLock`, do only:
   - `readLatch`
   - per-candidate dedupe check
   - `appendSystemMailbox`
   - `setLatchSignature`
   - one latch write if dirty

This preserves no-double-notify because concurrent sweepers serialize at the latch update. It also preserves persist-after-append because the latch is still written only after successful mailbox append.

I would not make shared heartbeat/pre-tool throttling the primary fix. It can reduce redundant work, but it also delays detection and becomes less important once the lock hold is tiny.

Add regression tests for:
- A thrown `LockTimeoutError` from sweep does not make `pre-tool-use` deny or throw.
- Candidate collection does not occur under `liveness-notifications.json.lock`.
- Existing `member-crash-notifications.test.js`, `member-crash-backstop-reset.test.js`, and listener delivery coverage stay green.
