**Technical Constraints**

- `.agents/memory/MEMORY.md` is not ignored by `.gitignore`; it should be tracked normally.
- `CLAUDE.md` is ignored, so only `AGENTS.md`, `.agents/memory/**`, and a docs file such as [docs/fork-notes.md](/d/harness-efforts/codexu/docs/fork-notes.md:1) can satisfy portable/git-tracked acceptance.
- Existing `MEMORY.md` uses relative Markdown links like `(feedback_phase_discipline_separate_members.md)`. Internal memory files also contain `[[wikilinks]]`, including both underscore and hyphen slug forms. Moving all files together preserves basename-based resolution, but plain Markdown readers will not auto-resolve wikilinks.
- I found no existing `@./...` include-directive precedent in `AGENTS.md`, `CLAUDE.md`, `.agents`, or `docs`. Do not make the migration depend on AGENTS include support unless separately confirmed.
- The worktree is dirty with many unrelated `.ralph`, `plans`, `tasks`, and submodule changes. Implementation should stage only `.agents/memory/**`, `AGENTS.md`, `docs/fork-notes.md`, and optionally local-only `CLAUDE.md`.
- Windows symlink creation is the riskiest step. Git Bash `ln -s` can be unreliable depending on MSYS settings. Prefer PowerShell `New-Item -ItemType SymbolicLink` if available, or an NTFS directory junction via `cmd /c mklink /J` as a practical equivalent for Claude Code’s directory reads.
