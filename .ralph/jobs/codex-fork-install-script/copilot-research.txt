### Technical Constraints

- There is no `codex install` subcommand. `install.ps1` must own install location and PATH wiring.
- Windows file locking matters: running `codex.exe` / `codex-core.exe` prevents replacement.
- Manual release skill and CI workflow are not identical. The workflow still contains GitHub Packages publish steps, while the manual skill says current distribution is GitHub Releases only and CI is blocked. The plan must choose the authoritative R2 upload path or explicitly update both.
- R2 credentials are external ops state. The code can consume `CLOUDFLARE_*` / S3-style secrets, but bucket, DNS, custom domain, lifecycle, and secret provisioning are operator-owned.
- `codex.evyatar.dev/latest` should be plain version text and guarded against HTML/error responses by the installer.
- The fork guidance strongly prefers wrapper/overlay changes over upstream-canonical Rust edits; this feature can avoid Rust code entirely.
