**Codebase Architecture**
This is a pnpm workspace monorepo with TypeScript across the relevant packages: `packages/happy-cli`, `packages/happy-app`, `packages/happy-server`, and `packages/happy-wire`. The relevant package is `packages/happy-cli`, a Node/ESM CLI using strict TypeScript, Vitest, `@/*` path aliases, and `@anthropic-ai/claude-agent-sdk`.

Claude execution is organized as:

- `packages/happy-cli/src/claude/runClaude.ts`: creates API session, tracks current permission/model/thinking state, queues user messages.
- `packages/happy-cli/src/claude/loop.ts`: switches between local and remote Claude modes.
- `packages/happy-cli/src/claude/claudeRemoteLauncher.ts`: owns remote SDK lifecycle, `PermissionHandler`, and session allowlist rehydration.

**Feature-Relevant Code**
The key invariant is in `packages/happy-cli/CLAUDE.md`: Happy has a 7-mode wire enum, Claude SDK only accepts 4 modes, and Claude-specific mapping must happen through `mapToClaudeMode`.

Relevant files:

  - `mapToClaudeMode(mode)` maps `yolo -> bypassPermissions`, `safe-yolo -> default`, `read-only -> default`.
  - Also contains `resolveInitialClaudePermissionMode()` and `applySandboxPermissionPolicy()`.

- `packages/happy-cli/src/claude/utils/permissionHandler.ts`

  - `handleModeChange()` correctly maps via `mapToClaudeMode()` at line 64.

**Technical Constraints**
Claude SDK `QueryOptions.permissionMode` is only `'default' | 'acceptEdits' | 'bypassPermissions' | 'plan'`. Happy’s shared `PermissionMode` is 7 values: `default`, `acceptEdits`, `bypassPermissions`, `plan`, `read-only`, `safe-yolo`, `yolo`.

`publishPermissionModeIfChanged()` mutates runner-local metadata before awaiting server update; do not disturb that behavior.

The handler’s internal `permissionMode` must always be a Claude SDK mode. Today the comment says that, but `handlePermissionResponse()` violates it at runtime if a non-Claude wire mode arrives.

**Implementation Suggestions**
Fix the narrow path in `packages/happy-cli/src/claude/utils/permissionHandler.ts`:

1. Widen `PermissionResponse.mode` from `ClaudeSdkPermissionMode` to the shared `PermissionMode`.
2. In `handlePermissionResponse()`, compute `const claudeMode = response.mode ? mapToClaudeMode(response.mode) : undefined`.
3. Assign `this.permissionMode = claudeMode`, not the raw response mode.
4. In the `ExitPlanMode` branch, use the mapped Claude mode when deciding `newMode`.
5. If TypeScript requires it, widen `PermissionsField.mode` in `claudeRemoteLauncher.ts` to the shared `PermissionMode` so logs can preserve the raw wire mode.

Add one regression test in `permissionHandler.test.ts`: create a pending permission, resolve it with `mode: 'yolo'` via the RPC handler, then assert a subsequent dangerous tool call is auto-allowed because `yolo` was mapped to `bypassPermissions`. The test may need the local test response type widened from the 4-mode enum to `PermissionMode`.
